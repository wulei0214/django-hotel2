## 2026-11-18（调度任务改为按需启用，本地默认停用）

  不写调度日志、不驻留进程；需要验证调度链路或真实部署时显式 `-Enable`。
- `scripts/install_scheduler_tasks.ps1` 新增 `-Disable` / `-Enable` 开关：只切换计划
  任务 State，不重写任务定义（因此不会因重复安装之外的操作悄悄恢复触发）；
  `-Uninstall` 在删除前先 `Stop-ScheduledTask` 停掉 Running 实例；三个开关均不再
  依赖 venv 存在性校验，避免环境变动后连停用都执行不了。
- 部署文档 Windows 段补「本地开发默认停用」语义与判定口径：以 `State=Disabled`
  为准，停用后 `NextRunTime` 仍保留上次计算值属正常现象；并注明脚本须先 `cd` 到
  仓库根或用绝对路径，否则 PowerShell 按当前目录解析相对路径，报「实际参数
  不存在」。
- 现状核验：六任务 `State=Disabled`、无 `pythonw`/`python` 残留进程、无本项目
  相关的开机自启项。
- 命令参考：四个开关的完整用法见 `scripts/install_scheduler_tasks.ps1` 头部注释（安装 /
  停用 / 启用 / 卸载）。

## 2026-11-18（MC-010 调度任务静默化修复）

- 现象：交互会话下反复弹出 Windows Terminal 空白窗口，标题为
  `F:\Desktop\django-hotel\.venv\Scripts\python.exe`；重启后仍复现。
- 根因（三处叠加）：①安装器动作使用控制台子系统 `python.exe` 且 `Hidden=False`；
  ②`payment_compensation_worker` 未传 `--once`，该命令默认 `while True` 循环，
  任务永不退出（窗口常驻，重启后再次触发即复现）；③并发触发时控制台创建失败
  返回 `0x800710E0`。另发现 `sync_inventory_calendar` 漏传命令强制的
  `--start-date/--end-date`，每天 02:30 以退出码 2 静默失败、从未成功。
- 修复：`scripts/install_scheduler_tasks.ps1` 改用 `pythonw.exe`，补 `Hidden`、
  15 分钟执行时限、`IgnoreNew`、10 年重复期与每任务独立日志；`scheduler_runner.py`
  支持 `--log=` 与 `{today}`/`{today+30}` 日期占位符（Windows 无 shell 日期运算）；
  `payment_compensation_worker` 补 `--once`；`sync_inventory_calendar` 补滚动 30 天窗口。
- 文档：`07_部署运维与数据治理/性能优化与生产部署升级说明.md` §三 改写 Windows
  口径（原 `cmd /c` + 手工 `schtasks` 写法即缺陷源头），cron 条目同步补 `--once`。
- 验证：六项任务强制触发 `LastTaskResult=0`；`WindowsTerminal` 与 `pythonw`
  残留进程均为 0；日志为单任务独立文件、含完整命令与退出码。
  证据 `acceptance/evidence/scheduler-silent-fix-20261118.log`。
