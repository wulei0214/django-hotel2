### 影响范围

### 验证

## 2026-11-02 — 修正员工生命周期校验与状态映射

### 修复内容
- 员工建档手机号查重不再排除同名档案，避免同名员工重复使用同一手机号。
- 员工暂停状态统一映射为 StaffProfile.INACTIVE + PropertyStaffMembership.SUSPENDED，避免把模型未定义的 SUSPENDED 写入档案状态字段。
- 生命周期服务拒绝未知员工状态；角色授权开始/结束时间统一处理时区，并在写库前拒绝结束时间不晚于开始时间的区间。
- 开通账号时拒绝空用户名，并在服务层拒绝空角色，避免依赖视图表单作为唯一校验边界。

### 影响范围
- 调整 apps/identity/services.py 与 apps/identity/tests.py；无数据库结构迁移。
- 更新根 README 的前台接待状态说明，并修订值班经理授权场景文档，明确业务权限必须通过 AuthorizationService / pms_permission_required 校验，不得使用 Django 全局 has_perm。

### 验证
- 新增员工手机号重复、暂停状态映射、非法状态、角色授权时间区间、时区归一化与空角色回归测试。
- 当前执行环境无法访问 GitHub 源码进行本地克隆，因此本轮未能执行 Django 测试；提交后以 GitHub Actions 对应 run 结果为准。

## 2026-10-30 — PMS 2.0 Phase 1 + Phase 2 文档归档与主干整合

### 新增/完成
- 建立物业上下文和单物业优先的数据隔离基础。
- 建立员工登录账号、员工自然人档案、物业任职关系、岗位授权记录的分层模型。
- 建立住客档案、房型、物理客房、房价计划、每日房价、按日库存模型。
- 建立 Reservation / ReservationRoom / Stay 的预订合同、房间明细与实际履约模型。
- 建立 Folio / Payment / LedgerEntry 账单、支付流水和不可变账本模型。
- 建立 API v1：可订查询、预订创建、预订查询/取消、Mock 支付意图/回调及 OpenAPI JSON。
- 新增顾客端 `/reserve/` 页面：通过 API 查询房型和逐晚价格、创建预订、查询订单、取消待支付预订，并在开发/测试环境演示模拟支付。
- 保留旧 `/booking/` 页面，避免未经回归直接替换旧流程。

### 修复/改进
- 预订库存按住宿日检查并在事务内锁定，避免只按单一总库存判断。
- 通过 Idempotency-Key 与请求指纹避免重复提交和同 Key 不同请求内容。
- 成交房价按晚保存快照，避免后续房价调整覆盖历史订单价格。
- 日期默认值使用本地日期字段格式化，避免 JavaScript UTC 转换造成日期偏移。
- 多间房的每间房金额按逐晚价格求和，避免总金额简单除以房间数造成分币舍入差异。
- 账本凭证禁止常规物理删除/直接修改，改用冲销凭证思路。

### 影响范围
- 新增/调整：`apps/core`、`apps/identity`、`apps/guests`、`apps/inventory`、`apps/reservations`、`apps/billing`、`apps/api`。
- 路由：新增 `/reserve/` 与 `/api/v1/*`。
- 文档：新增技术架构、开发指南、UI 指南与本变更记录；重写根 README 为当前真实项目状态。

### 界面变化
- 新增顾客端页面 `/reserve/`，使用 Django 模板 + 原生 JavaScript。
- 本次未修改旧后台管理页面；旧截图不得作为新顾客端 UI 截图使用。
- 当前仓库未包含新页面运行态截图；需在本地配置数据并运行后重新截取，后续替换 UI 文档中的截图资产。

### 验证
- Phase 1 / Phase 2 GitHub Actions 检查均显示成功；合并前再次核对分支最新 SHA 的 CI 状态。
- 本地 MySQL/PostgreSQL 并发压力测试仍需在真实数据库环境执行。

### 版本约束
- PMS 3.0 只做已有功能完善、Bug 修复、性能/安全/兼容优化和回归，不新增业务功能。
