## 1. 决策目的

统一 OCC、ADR、RevPAR、营业收入和实收的统计口径，避免运营看板、报表 API、导出和财务账本各自采用不同分子、分母或日期口径。所有报表必须能回溯其数据来源和计算边界。

## 2. 正式批准的指标口径

### 2.1 OCC（入住率）

`OCC = 已售间夜 ÷ 可售间夜 × 100%`

- 可售间夜 = 统计期间内总房间数对应的房间夜 − 停用房间夜。
- 停用房间夜从分母剔除。
- 已售间夜按本决策定义的有效已售房间夜统计；不得将取消、No-show 或仅有预订但未形成实际入住的记录当作已售间夜。
- OCC 是本项目的运营统计指标，不等同于物理房间占用率；如需统计免费房或内部用房的物理占用，应另设独立指标，不得混入付费已售间夜。

### 2.2 ADR（平均每日房价）

`ADR = 已过账 ROOM_CHARGE 凭证净额 ÷ 付费已售间夜`

- 分子以已过账 LedgerEntry 中的 ROOM_CHARGE 凭证为准。
- 红字冲销、反向更正凭证按其正负符号计入净额，不得忽略。
- 分母只计付费已售间夜；免费房和内部房不计入 ADR 分母。
- 税费不计入房费净额。
- 不得使用 Payment 金额替代 ROOM_CHARGE 收入。

### 2.3 RevPAR（每间可售客房收入）

`RevPAR = 已过账 ROOM_CHARGE 凭证净额 ÷ 可售间夜`

- 分子与 ADR 使用同一房费净额口径。
- 分母与 OCC 使用同一可售间夜口径。
- 税费、押金、退款现金流和渠道佣金不得直接混入 ROOM_CHARGE 房费净额。

### 2.4 营业收入

- 营业收入以已过账 LedgerEntry 作为权威事实来源。
- Payment 是资金收付事实，不等于营业收入。
- 退款、押金、负债结转、现金流水不得被错误归类为房费营业收入。
- 冲销必须以带符号的账本凭证体现，不允许通过覆盖原凭证改变历史统计。

### 2.5 实收

`实收 = 成功 Payment − 成功 Refund`

- 仅统计成功状态的资金交易。
- 实收与营业收入分开呈现，不得合并成一个“收入”指标。
- 押金、退款和其他资金项目应按交易类型单独展示，不能因现金已收取就认定为收入。

## 3. 特殊房态和交易边界

| 场景 | OCC / 已售间夜 | ADR | RevPAR / 房费收入 |
|---|---|---|---|
| 正常付费入住 | 按有效已售间夜统计 | 计入 | 按已过账 ROOM_CHARGE 计入 |
| 免费房（Complimentary） | 不计入付费已售间夜；物理占用如需统计应另列 | 不计入分母 | 不产生虚构 ROOM_CHARGE |
| 内部房（House Use） | 不计入付费已售间夜；物理占用如需统计应另列 | 不计入分母 | 不产生虚构 ROOM_CHARGE |
| 停用房 | 不计入可售间夜分母 | 不直接影响分子 | 不直接影响分子 |
| 取消预订 | 不计入已售间夜 | 不计入 | 不计入房费收入 |
| No-show | 不计入实际已售间夜 | 不计入 | No-show 费用不得伪装成 ROOM_CHARGE |
| 提前离店 | 按实际履约及已过账房费处理 | 按实际付费已售间夜 | 未住晚数违约金不得伪装成 ROOM_CHARGE |
| 红字冲销 | 不改变历史物理间夜事实 | 按带符号凭证调整房费净额 | 按带符号凭证调整房费净额 |
| 税费 | 不改变间夜 | 不计入房费分子 | 不计入 ROOM_CHARGE 净额 |
| 渠道佣金 | 不改变间夜 | 不直接冲减 ADR 房费分子 | 作为渠道费用单独核算 |

## 4. 多币种、日期与元数据

1. 多币种必须分币种展示，不得把不同币种金额直接相加。
2. 在汇率来源、汇率时点、折算方向和审计留痕未形成独立批准基线前，不允许跨币种折算汇总。
3. 核心财务报表优先按物业 business_date 统计；自然日趋势必须明确标注为自然日口径。
4. 所有日期边界使用物业时区；不得使用服务器本地时区替代。
5. 每项指标的 API 响应和导出必须提供口径 metadata，至少包括：指标定义、分子、分母、日期依据、状态范围、币种、物业时区和生成时间。
6. 无法取得必要元数据或来源数据不完整时，必须显式返回缺失/不完整状态，不得静默填零或伪造统计结果。

## 5. 实施与验收要求

以下是已批准口径的实现验收要求，不代表相关功能已经全部实现：

- OCC、ADR、RevPAR 的 API、页面和导出使用同一指标服务或同一权威计算逻辑。
- 以逐笔 LedgerEntry 和房型/房间库存事实核对分子、分母。
- 建立人工可复算的固定样例，覆盖正常付费、免费房、内部房、停用房、取消、No-show、提前离店、红字冲销、税费和多币种。
- 手工计算结果、API 响应、页面展示和导出结果必须一致。
- 实收必须独立验证成功 Payment 与成功 Refund 的净额，不能用营业收入替代。
- 必须验证跨 business_date 边界、物业时区和币种隔离。
- 未实现的指标端点或元数据字段必须在交付报告中列为未完成，不得以现有运营看板代替验收。

## 6. 权威数据来源与禁止事项

| 数据事实 | 权威来源 |
|---|---|
| 房费收入及冲销 | 已过账 LedgerEntry |
| 资金实收/退款 | 成功 Payment / Refund |
| 房间可售与停用 | 房间/房型库存及停用事实 |
| 实际入住间夜 | ReservationRoom / Stay 的有效履约事实 |
| 营业日 | 物业 business_date 规则 |

禁止：
- 以 Payment 代替营业收入；
- 将押金、退款、税费、渠道佣金混入 ROOM_CHARGE；
- 把免费房或内部房伪造为有房费收入；
- 将不同币种直接相加；
- 通过覆盖历史凭证修正报表；
- 在指标尚未完成逐笔对账前宣称会计报表验收通过。
