# PMS2 七类角色用户旅程与端到端验收规范（ARCH-13）

> 文档编号：ARCH-UJ-001 ｜ 类型：GOVERNANCE ｜ 状态：ACTIVE ｜ 版本域：PMS2.0 ｜ 业务模块：全业务中心
> 任务依据：PMS2-ARCH-GOV-001 V1.1 第 13 章（ARCH-13）。
> 证据基线：`main@2604b19`（2026-11-25 现取现核）。
> 纪律：**只写已实现能力**。未开发的在线预登记、OCR、自助退房、免查房退房一律标注「未实现」，不得画成已具备。

## 0. 角色口径

七类角色（与任务书一致）：顾客、前台、财务、值班经理、客房人员、管理人员、夜审人员。

九岗位 RBAC（授权事实源 `apps/identity/registry.py`）与其映射关系：

| 任务书角色 | 对应 RBAC 岗位 | 说明 |
|---|---|---|
| 顾客 | 匿名 / 客人会话 | 无员工任职，仅公开面 + Booking Access Token |
| 前台 | 前台 | 接待、排房、收退款申请 |
| 财务 | 财务 | 收款登记、退款执行、对账 |
| 值班经理 | 值班经理 | 审批、异常放行、运营协调 |
| 客房人员 | 客房服务员 | 清洁/维修任务执行 |
| 管理人员 | 店长 | 经营数据、权限、审计 |
| 夜审人员 | 夜审员 | 营业日检查与夜审执行 |

> 餐饮服务员、餐饮主管、停车安保为九岗位中的另三个岗位，本任务书七角色不含其旅程；其权限面见 NS-E-05 九岗位矩阵。

## 1. 顾客旅程

| 项 | 内容 |
|---|---|
| 用户目标 | 查询可订房型 → 完成预订 → 到店入住 → 退房 |
| 权限 | 匿名可查价与下单；订单访问凭 Booking Access Token，不接受手机号作为凭据 |
| 页面入口 | `/reserve/`（公开直订页）；`/booking/` 已冻结 302 → `/reserve/` |
| 操作步骤 | 选日期房型 → 看价格与取消规则 → 填住客信息 → 提交 → 支付（或按 RatePlan 无预付）→ 收到 booking_no + token → 到店前台核验 → 入住 → 退房 |
| 前端反馈 | 房量不足 / 暂不可预订 与 无价格 分别提示（`select_rate_plan_for_room_type` 口径）；错误走统一错误封套 |
| API | `GET /api/v1/availability`、`POST /api/v1/reservations`、`GET/POST /api/v1/reservations/<booking_no>`、`POST /api/v1/reservations/<booking_no>/cancel`、`POST /api/v1/payments/intents`、`POST /api/v1/payments/callback` |
| 后端服务 | `apps/reservations/services.create_reservation`、`apps/billing/services.create_mock_payment_intent`、`process_mock_payment_callback` |
| 数据模型 | Guest、Reservation、ReservationRoom、RoomTypeInventory、Payment、PaymentIntent、ProviderTransaction |
| 事务边界 | 建单（库存 Hold + 金额 + 订单）原子；回调（Payment + 账本 + 库存确认）原子 |
| 状态变化 | Reservation PENDING→CONFIRMED；Payment PENDING→SUCCEEDED |
| 数据范围 | 仅自己 booking_no + token |
| 审计 | `guest.booking_access_denied`、`billing.mock_callback_intent_skipped_unsigned`、限流 `public.rate_limited` |
| 异常分支 | 重复提交（幂等键）、支付失败、取消后库存恢复、token 错误 404 |
| 后续影响 | 确认后生成待办/通知；退房后房态转 DIRTY 并生成清洁任务 |
| 测试证据 | `apps/api/test_public_booking_lifecycle.py`、`apps/billing/tests.py`；e2e 链 A |

**未实现（不得宣称）**：在线预登记、OCR 证件识别、自助退房、免查房退房。

## 2. 前台旅程

| 项 | 内容 |
|---|---|
| 用户目标 | 接待客人：查询/处理预订、排房、入住、收款押金、换房、续住、退房、异常升级 |
| 权限 | `hotelapp.view_accommodation` + `change_accommodation`；**无** `finance_access`（不得进财务中心）；退款只能发起申请，不能审批/执行 |
| 页面入口 | `/checkin/` 前台接待工作台 |
| 操作步骤 | 登录 → 工作台（今日预抵/在住/离店）→ 检索客人 → 核验身份 → 排房 → 办理入住 → 收押金/收款 → 换房/续住 → 退房 → 异常交值班经理 |
| 前端反馈 | 房态与订单状态实时；账务口径区分「已入账」与「合同应收」（`_folio_summaries`） |
| API | `/api/v1/front-desk/*`（overview/arrivals/departures/in-house/reservations/rooms/assign/check-in/check-out/extend/change-room/deposits/payments/refunds/request） |
| 后端服务 | `apps/reservations/front_desk_services.py`、`lifecycle_services.py` |
| 数据模型 | 上述 Reservation/Stay/Room/Folio/Payment |
| 事务边界 | 每个写操作整体原子（入住、退房、换房、续住、收款） |
| 状态变化 | Reservation/Stay/Room/Folio 联动 |
| 数据范围 | 当前物业；已认证但无 DEFAULT 任职 → 403 并审计 |
| 审计 | `frontdesk.checked_in` / `checked_out` / `stay_room_changed`、`housekeeping.task_created` |
| 异常分支 | 不可用房间、重复入住、账务未清、营业日已关账、越权 |
| 后续影响 | 清洁任务、待办、报表 |
| 测试证据 | `apps/reservations/tests.py`、`apps/api/test_e2e_flows.py`、九岗位矩阵（90/90） |

## 3. 财务旅程

| 项 | 内容 |
|---|---|
| 用户目标 | 收款/支出登记 → 收款核对 → 退款执行 → 对账 → 报表 |
| 权限 | `hotelapp.finance_access`；退款 **执行** 权（审批归值班经理/店长）；不得审批自己申请 |
| 页面入口 | `/manage/finance/` 财务中心 |
| 操作步骤 | 查看待处理 → 人工收款登记 → 核对流水 → 收到已批准退款 → 执行（现金需本人班次）→ 对账扫描 → 报表 |
| API | `/api/v1/billing/payments`、`/api/v1/billing/refunds/<id>/execute`、对账/报表端点 |
| 后端服务 | `apps/billing/services_v2.BillingService`（`collect_payment`、`approve_refund`、`execute_refund`、`post_entry`、`reverse_entry`） |
| 数据模型 | Payment、Refund、RefundLiability、LedgerEntry、CashierShift、ApprovalRecord |
| 事务边界 | 执行退款（账本 + Refund + 负债 + Payment 汇总）原子 |
| 状态变化 | Refund APPROVED→SUCCEEDED；Payment→PARTIALLY_REFUNDED/REFUNDED |
| 数据范围 | 本物业全部财务；敏感字段按既有矩阵脱敏 |
| 审计 | `billing.refund_approved/executed/expired`、账本不可变 |
| 异常分支 | 未审批执行、申请人=执行人、超额、现金班次缺失、重复执行 |
| 后续影响 | 负债冲减、报表口径、对账差异 |
| 测试证据 | `apps/api/test_refund_dual_entry.py`、`test_billing_center.py`、`test_cashier_reconcile.py` |

## 4. 值班经理旅程

| 项 | 内容 |
|---|---|
| 用户目标 | 运营监控 → 处理异常 → 授权/审批 → 协调交接 |
| 权限 | 审批权限（退款审批、冲销审批、营业日重开）；异常放行审批；**不得**替代财务执行 |
| 页面入口 | `/manage/night-audit/`、`/manage/finance/`（审批视图） |
| 操作步骤 | 看待审批/异常 → 核验业务对象 → 通过/驳回（原因必填）→ 异常放行审批 → 交接 |
| API | `/api/v1/front-desk/refunds/<id>/approve|reject`、`/api/v1/approvals/<id>/approve|reject` |
| 后端服务 | `ApprovalService.approve/reject`、`BillingService.approve_refund`、`NightAuditService.approve_reopen` |
| 数据模型 | ApprovalRecord、Refund、BusinessDate |
| 事务边界 | 审批与业务对象状态同事务 |
| 状态变化 | ApprovalRecord PENDING→APPROVED/REJECTED/EXPIRED |
| 数据范围 | 本物业 |
| 审计 | `billing.refund_approved`、`billing.reversal_approved`、审批不可删除 |
| 异常分支 | 同人审批拒绝、跨物业 404、已终态冲突 |
| 测试证据 | `apps/api/test_approval.py`（30+ 负向用例）、九岗位矩阵 |

## 5. 客房人员旅程

| 项 | 内容 |
|---|---|
| 用户目标 | 接任务 → 清洁/维修 → 上报异常 → 完成 → 房态更新 |
| 权限 | `inventory.housekeeping_update`；净房放行需 `hotelapp.room_release_ready`（管理者） |
| 页面入口 | `/manage/housekeeping/` |
| 操作步骤 | 任务池 → 领取/开始 → 清洁中 → 完成 → 检查（他人）→ 净房放行 |
| API | `/api/v1/housekeeping/tasks/<id>/claim|start|complete|inspect` |
| 后端服务 | `apps/inventory/services_housekeeping_tasks.py` |
| 数据模型 | HousekeepingTask、RoomInspection、Room、MaintenanceTicket |
| 事务边界 | 任务状态 + 房态同事务 |
| 状态变化 | PENDING→IN_PROGRESS→DONE→INSPECTED；REJECTED 回 IN_PROGRESS；房态 DIRTY→CLEANING→INSPECTING→CLEAN |
| 数据范围 | 本物业；**不得**查看无关客人敏感信息 |
| 审计 | `housekeeping.task_claimed/started/completed/inspected` |
| 异常分支 | 自检放行被拒、检查不通过须填不合格项、已关单不可再操作 |
| 测试证据 | `apps/api/test_housekeeping_workflow.py`（链 B e2e 9/9） |

## 8. 角色交接触点

| 交接 | 触发 | 载体 |
|---|---|---|
| 顾客 → 前台 | 到店 | Reservation + Booking Access Token |
| 前台 → 值班经理 | 账务异常/超额退房/异常放行 | 审批申请 |
| 前台 → 财务 | 退款已批准 | Refund APPROVED 待执行 |
| 财务 → 值班经理 | 冲销需审批 | ApprovalRecord |
| 前台 → 客房 | 退房/报修 | HousekeepingTask / MaintenanceTicket |
| 夜审 → 前台/财务 | 关账后写操作拒绝 | BusinessDate CLOSED 守卫 |
| 任何角色 → 管理 | 审计/报表 | AuditEvent / Report |
