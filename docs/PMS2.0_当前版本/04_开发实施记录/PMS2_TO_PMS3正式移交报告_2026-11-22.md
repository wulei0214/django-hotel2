## 四、PMS 3.0 开发边界与禁止重复清单

### 4.1 必须原样继承（禁止重建）

| 业务事实 | 权威归属 | 禁止行为 |
|---|---|---|
| 员工身份与任职 | `apps.identity` | 不得用 `User.groups` 作业务权限权威 |
| 顾客与住客档案 | `apps.guests` | 不得新建第二套客人主表 |
| 房间/房型/库存/价格 | `apps.inventory` | 不得再造库存占用系统 |
| 预订与入住履约 | `apps.reservations` | 不得再造预订系统 |
| 账单/收款/退款/账本 | `apps.billing` | 不得再造账本；禁止覆盖历史凭证 |
| 营业日与夜审 | `apps.core` + billing | 禁止自动重跑高危不可逆操作 |
| 审计事件 | `apps.core` | 不得用普通日志替代 |
| 通知与待办 | `apps.core` | 不得成为第二套业务状态系统 |
| HTTP API 契约 | `apps.api` + OpenAPI | 不得绕过 Service 直写 |

### 4.2 开发继承规则

1. 先 Model/Service，再 API/UI；
2. 每项开发必须有 DEC 记录、测试、审计与回滚方案；
3. 业务改动必须有迁移方案；
4. 不允许直接重写 PMS 2.0 已稳定模块；
5. 新增业务事实前必须核对本表是否已有权威归属。
