## 一、R1-01 现状核实结论（开工前已核实，本批复证一致）

DEC-RF-01 与现有实现（`apps/billing/services_v2.py` `BillingService.execute_refund` + `post_entry`/`_create_entry_record`）逐条对照：

| # | DEC-RF-01 要求 | 实现位置 | 结论 |
| --- | --- | --- | --- |
| ① | 退款凭证 business_date=执行时物业时区营业日 | services_v2.py `execute_refund` 内 `post_entry(business_date=BillingService._business_date(property_obj))`（`_business_date` 用 `timezone.localdate(timezone.now(), ZoneInfo(property.timezone))`） | 一致 |
| ② | CLOSED 营业日拒执行、Refund 保持 APPROVED | WB-079 关账守卫（`_create_entry_record`：目标 `(property, business_date)` 存在 `BusinessDate.Status.CLOSED` 记录即拒），守卫在 `execute_refund` 的 `post_entry` 处触发 → 整个 atomic 回滚 → REFUND 无凭证、无执行人/执行时间/执行幂等键残留 | 一致 |
| ③ | 原订单/原支付/原营业日可溯 | REFUND 凭证 `reference=f"refund:{refund.provider_ref}"` → 反查 Refund → `refund.payment_id` → Payment → folio/reservation → 原收款凭证 `reference=f"payment:{provider_ref}"` 携带原营业日 | 一致 |
| ④ | execution_idempotency_key 幂等 | `execute_refund` 同键重放返回 `(refund, False)` 不重复入账；异键重放已执行退款明确拒绝；键全局唯一约束兜底 | 一致 |

**无冲突需登记；R1-02/R1-03 为测试固化而非行为修改。**

## 二、交付清单与实施说明

### 2.1 R1-02/R1-03：`apps/billing/test_refund_business_day.py`（新建，6 项）

夹具风格对齐 `apps/billing/test_cashier_reconcile.py`：自建物业（timezone=Asia/Shanghai）+ 申请/审批/执行三方账号分离；支付/退款/凭证一律经 `BillingService.collect_payment / request_refund / approve_refund / execute_refund` 真实服务构造；营业日关账按任务书以简单者为先——直接构造 `BusinessDate.Status.CLOSED` 记录（等价夜审 run 终态）；「次日推进」用 `mock.patch("django.utils.timezone.now", +1 天)` 驱动 `_business_date` 并 `get_or_create` 新 OPEN 营业日。

| 测试名 | 固化口径 |
| --- | --- |
| `test_refund_executes_on_open_business_day` | ① OPEN 营业日执行 → SUCCEEDED；REFUND 凭证 business_date=当前营业日、金额/folio 一致 |
| `test_refund_rejected_on_closed_day_keeps_pending_state` | ② 当日已关账（直接构造 CLOSED 记录）→ execute 抛"已关账"，Refund 保持 APPROVED 待处理（executed_by/executed_at/execution_idempotency_key 均无残留，无 REFUND 凭证）——DEC-RF-01 第 5 条 |
| `test_refund_executes_next_day_after_business_day_advances` | ③ 关账拒执行 → 营业日推进（次日 OPEN 日 get_or_create）→ 同一 refund 以同幂等键重试成功，凭证归属新营业日（≠当日）——"次日开放营业日执行" |
| `test_refund_ledger_attribution_traceability` | ④ REFUND 凭证 reference 反查 Refund → 原支付 → 原订单/账单；原收款凭证（`payment:{provider_ref}`）business_date=原营业日，与退款执行营业日形成归属对照 |
| `test_execution_idempotency_same_key_replay` | ⑤ 同键重放返回 `(refund, False)`、凭证不重复（账面 PAYMENT+REFUND 各一笔）；异键重放已执行退款明确拒绝 |
| `test_no_open_business_day_pauses_execution` | ⑥ 物业全部营业日记录均已关账（前一日+当日 CLOSED）、无任何 OPEN 日、次日未建 → 执行拒、APPROVED 保留、无 REFUND 凭证 |

**口径注记（防未来误改，已写入测试 docstring）**：WB-079 暂停条件是「目标营业日记录为 CLOSED」；营业日完全无记录（白天未到夜审时点的正常态）按隐式开放放行、不暂停——若未来收紧为"必须有 OPEN 记录才能执行"，`test_no_open_business_day_pauses_execution` 的前置自证断言与口径注记将捕获该行为变化。
