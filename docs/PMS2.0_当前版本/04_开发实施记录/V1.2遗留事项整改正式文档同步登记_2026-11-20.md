## 一、为什么需要本登记

V1.2 轮不改写任何历史文档，也不重跑整轮整改；但以下三处**代码契约**发生了
对外可见的变化，若不同步登记，后续按旧文档实现的调用方会出现口径错位：

| 变化 | 旧口径 | 新口径 |
|---|---|---|
| 预订计费类型 | 只有"过夜"，`check_out > check_in` 是硬约束 | 新增显式 `billing_type`（`NIGHT_STAY` / `DAY_USE`）；日租 `check_out == check_in` |
| 日租价格来源 | 无（日租业务无法下单） | 物业×房型×生效区间的 `billing.DayUsePolicy`，缺政策即拒绝 |
| 前台账单摘要 | 只有"当前未结应收"三个数字 | 增补 `closed_folio_count / closed_charges / closed_credits` 历史口径（不并入应收） |

## 二、数据模型（02_技术架构与数据模型 口径）

| 对象 | 变更 | 权威位置 | 迁移 |
|---|---|---|---|
| `reservations.Reservation` | 新增 `billing_type`（`TextChoices`：`NIGHT_STAY` / `DAY_USE`，默认 `NIGHT_STAY`）；`ck_reservation_checkout_after_checkin` 约束按类型分流 | `apps/reservations/models.py` | `reservations/0012_reservation_day_use_billing` |
| `reservations.ReservationRoom` | 同上分流 `ck_reservation_room_checkout_after_checkin`；新增 `day_use_price` 政策价快照 | 同上 | 同上 |
| `billing.DayUsePolicy`（新表） | `property × room_type × valid_from` 唯一；`day_use_price / start_time / end_time / grace_minutes / overtime_hourly_rate / valid_from / valid_to / is_active`；约束：`end_time > start_time`、`valid_to >= valid_from`、`day_use_price > 0`；索引 `ix_dayuse_prop_type_active` | `apps/billing/models.py` | `billing/0036_day_use_policy` |
| `billing.RoomAssignmentConflict` | 新增可空唯一键 `open_key`（`OPEN` 时 = `room_id:stay_date`，其余 `NULL`）+ 唯一约束 `uq_room_conflict_open_key`，由 `save()` 维护、迁移回填 | 同上 | `inventory/0011_room_conflict_open_key` |

口径要点（写进本登记防止再解释）：

- 日租的"占用日"是 `[check_in, check_in + 1 天)`，排房冲突判定必须按此展开，
  否则两条同日日租会被排进同一间房。
- `open_key` 只用于**并发扫描**的数据库级仲裁；历史重复 `OPEN` 行**不自动关闭**，
  由人工核对后处理（迁移只给同组最小 pk 回填键值）。

## 三、API 契约（03_API接口与前后端规范 口径）

OpenAPI 快照已同步：`docs/PMS2.0_当前版本/03_API接口与前后端规范/接口文档/openapi.json`
与镜像 `docs/接口文档/openapi.json`（两份逐字节一致，SHA-256
`525BFC35DCD3DFB3A7403A2DA9A1370D38880EF039141904284390ADBA06BB9C`，168 paths）。

| 端点 | 变更 | 说明 |
|---|---|---|
| `POST /api/v1/front-desk/walk-ins` | 请求体新增 `billing_type`（`enum: NIGHT_STAY / DAY_USE`，默认 `NIGHT_STAY`）；`nights` 语义调整（`minimum` 0） | `DAY_USE` 时服务端强制 `nights=0`，房费按 `DayUsePolicy` 政策价一次性入账；无政策→400/409 拒绝，不回落过夜价、不按 0 元 |
| `GET /api/v1/front-desk/reservations/<booking_no>` | `folio_summary` 新增 `closed_folio_count / closed_charges / closed_credits` | **当前应收契约不变**：`charges/credits/balance` 仍只统计 `OPEN` 账单 |
| `GET /api/v1/front-desk/folios/<booking_no>` | 不变（返回账单**全量**流水 `charges/credits/balance`） | 与上一行口径不同：前者是"当前未结应收"，后者是"账单全量"。前端已用不同标签区分（见 §四） |
| `POST /api/v1/front-desk/walk-in` | 不变（恒 410 Gone） | 见 `V12-09` |

## 八、未同步项与边界

1. 本登记**不替代**既有需求/架构/API 文档正文的逐条改写：只在"契约确实变了"的
   三点上给出新口径与权威位置，避免制造第二份互相矛盾的正文。

   不能留空。属实现现状，未在本轮改为可空（会牵动既有唯一约束与解析规则）。
