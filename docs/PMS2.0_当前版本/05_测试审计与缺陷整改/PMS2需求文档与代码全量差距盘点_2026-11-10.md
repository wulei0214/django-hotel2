## 二、已确认决策但尚未开发的六项业务规则

### 2.1 DEC-ED-01 提前退房结算

**现状**：`check_out_stay()` 以 `ReservationRoom.amount` 减已过账房费作为退房补记目标；无 EarlyDeparturePolicy 模型；未来住宿日期库存释放未闭环。

**待开发**：
- [ ] 独立 EarlyDeparturePolicy 模型（RatePlan 关联、5 种政策类型 NONE/FIRST_NIGHT/FIXED/PERCENT_UNUSED/REMAINING_NIGHTS）
- [ ] 预订确认时保存政策版本快照
- [ ] 退房时按实际入住晚数 + nightly_rates 快照重算（替代 amount 净额）
- [ ] 违约金独立凭证（非 REFUND 类型）
- [ ] 未住日期库存释放走 InventoryService
- [ ] 测试：多房单间提前离店、夜审已过账差额、政策快照隔离

**阻塞**：各 RatePlan 的具体违约金类型/数值和政策快照规则需业务配置（默认 NONE，可先行开发框架）。

### 2.2 DEC-DEP-01 押金政策 30%

**现状**：`DepositPolicy` 模型存在（NONE/FIXED/PERCENT + deposit_value + due_before + refundable），但 `BillingService.record_deposit()` 由调用方传金额，**不读取政策模型**，无 30% 自动计算。

**待开发**：
- [ ] `record_deposit()` 接入 DepositPolicy：按 reservation.total_amount × 30% 服务端计算
- [ ] 客户端传入金额仅用于展示核对，不得作为最终金额来源
- [ ] 记录政策 ID/版本、计算基数、比例、应收金额快照
- [ ] Walk-in 使用同一政策计算服务
- [ ] 测试：1000 元房费→押金 300；前端篡改金额无效；重复收款拒绝

**不阻塞**：30% 是已确认的默认值，可直接开发。

### 2.3 DEC-EMP-01 员工重新入职

**现状**：`PropertyStaffMembership` 存在 `(property, staff_profile)` 永久唯一约束，阻止同一员工同一物业保留多条历史任职。

**待开发**：
- [ ] 移除阻止历史任职的唯一约束
- [ ] 增加"同一员工同一物业最多一条有效任职"的并发安全机制
- [ ] EmployeeLifecycleService 支持重新入职流程（旧任职终止 → 新任职创建）
- [ ] 离职撤销会话/授权；重新入职重新分配
- [ ] 测试：离职→再入职、并发创建、跨物业独立、权限不继承

**不阻塞**：约束迁移和生命周期服务可先行开发。

### 2.4 DEC-EMP-02 员工工号自动生成

**现状**：`employee_no` 由调用方传入，`create_employee()` 只负责查重，无自动编号服务。

**待开发**：
- [ ] 编号序列表（property + department_code 维度递增）或等价并发安全机制
- [ ] `create_employee()` 原子分配流水号（事务内）
- [ ] 离职工号永久保留不回收
- [ ] 员工导入历史工号映射和冲突报告
- [ ] 测试：连续生成/不同部门独立递增/并发不重复/离职不回收

**不阻塞**：部门代码目录（FO/HK/FIN/MG/ENG）已确认，可直接开发。

### 2.5 DEC-PII-01 证件留存与清理

**现状**：`GuestDocument.retention_until` 字段存在，但无到期清理任务、无 legal hold 元数据、无审批流程。

**待开发**：
- [ ] 留存策略配置（按证件类型/辖区设置期限）
- [ ] 到期清理管理命令（dry-run → 预览 → 审批 → 执行）
- [ ] legal hold 元数据阻止清理
- [ ] 密钥轮换支持
- [ ] 测试：不同证件类型不同策略 / legal hold 阻止 / dry-run 不改数据

**阻塞**：经营辖区、证件类型及期限需业务/法务确认。框架可先行开发，不启用自动删除。

### 2.6 DEC-WALKIN-01 Walk-in 散客入住

**现状**：`Reservation.source` 已有 WALK_IN 枚举值，但无原子化 Walk-in 创建服务（Guest→Reservation→ReservationRoom→Folio→Stay 不在同一事务中）。

**待开发**：
- [ ] 原子化 Walk-in 创建服务（Guest→Reservation→Room→Folio→Stay 同事务）
- [ ] 押金计算走 DEC-DEP-01 政策服务
- [ ] 库存校验走 InventoryService
- [ ] 幂等键 + 审计
- [ ] 测试：Walk-in 全链路 / 无手机号兼容 / 重复提交 / 孤儿记录不产生

**阻塞**：手机号可选的辖区适用性确认后可开放生产入口；开发可先行。
