## 1. 根因与影响

迁移 0035 已为 `LegacyArchiveRecord` 抽象基类增加可空 `property` 外键，四张归档表均获得 `property_id`。但此前归档写入服务没有给该字段赋值，归档行会全部保留 NULL；归档查询仍只按 `LegacyMigrationBatch.scope_property` 做批次级授权，没有按归档行的物业快照过滤。与此同时，非超管调用 `list_batches(property_obj=None)` 时原实现不会拒绝，存在跨物业批次元数据暴露风险。

影响：
- FIN-02 的数据库结构已经存在，但归档数据和 D6 查询通道未真正消费该字段；
- 物业级过滤只靠批次范围，无法证明每条历史记录的物业归属；
- 缺少物业上下文的批次列表调用未 fail-closed；
- 归档写入成功后若审计记录失败，旧实现可能留下无对应审计的归档数据。

## 2. 实现内容

### 2.1 逐记录物业快照写入

涉及：`apps/billing/legacy_archive.py`

- `archive_table` 增加 `property_assignments` 参数，键为源表主键，值为已存在的 `Property`。
- 映射包含当前源表不存在的主键、无效物业对象，均拒绝归档。
- 若存在已登记迁移批次，逐条映射物业必须与批次 `scope_property` 一致。
- 未提供映射的源记录写入 NULL；不从 DEFAULT、房号、客人、订单关系或批次范围推断。

### 2.2 归档命令映射文件

涉及：`apps/billing/management/commands/archive_legacy_finance.py`

新增参数：

```bash
python manage.py archive_legacy_finance \
  --batch-uid FIN-D3-DEFAULT-001 \
  --operator "finance-operator" \
  --tables Folio,FinanceRecord,NightAudit,Accommodation \
  --property-map-file /secure/evidence/fin02-property-map.json \
  --dry-run
```

JSON 格式：

```json
{
  "Folio": {"9001": "DEFAULT"},
  "FinanceRecord": {"7001": "DEFAULT"},
  "NightAudit": {"6001": "DEFAULT"},
  "Accommodation": {"8101": "DEFAULT"}
}
```

- 顶层键必须是所选来源模型名称，子键为源表主键，值为 `Property.code`。
- 未确认记录应省略，不允许用空物业代码表达推测归属。
- 文件、模型、主键和物业代码均校验；dry-run 输出每张表已确认/未确认数量。
- 物业快照是归档分类元数据，不混入 checksum-v2 的源字段摘要。

### 2.3 归档查询双层隔离

涉及：`apps/billing/legacy_archive_query.py`

- 非超管必须提供物业上下文；
- 当前物业必须与迁移批次 `scope_property` 一致；
- 明细查询按归档行 `property_id` 再过滤；
- NULL/未确认物业归属记录不向财务角色开放，仅平台超管可查；
- 非超管批次列表缺失物业上下文时直接拒绝。

### 2.4 归档与审计原子性

涉及：`apps/billing/management/commands/archive_legacy_finance.py`

归档行、`LegacyArchiveRun` 批次元数据和 `billing.legacy_archive` 审计事件置于同一事务。审计事件写入失败时整体回滚，不允许形成无审计归档。

## 6. 归档命令安全默认值补丁（2026-11-17）

复核发现原 archive_legacy_finance 命令只有 --dry-run 开关，不传该参数时会直接写归档表。该默认行为不符合“默认只读、生产写入必须显式授权”的治理要求，已修正：

- 不传执行模式参数时，默认执行 dry-run；只读取旧表并输出统计，不写归档行、LegacyArchiveRun 或 AuditEvent。
- --dry-run 与默认行为一致；--verify 只重算已有归档批次摘要，均为只读模式。
- 写入必须显式传入 --execute；--execute 与 --dry-run / --verify 互斥。
- --execute 还必须提供 --batch-uid、--operator、--approval-ref；approval_ref 长度 1-128 字符。
- approval_ref 会写入 billing.legacy_archive 审计事件的 after 与 reason，便于追溯。该参数只是审批记录引用，不会验证文件签名或代替负责人实际签署。
- 新增默认 dry-run 零写入、执行参数缺失拒绝、模式互斥测试；test_legacy_archive.py 当前共 21 条测试。
- 本补丁只修改命令、测试和文档；没有执行任何生产归档，也没有更改 D1-D6 门禁。
