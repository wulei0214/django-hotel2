### 2.3 约束分层（复核发现，需知悉）

数据库层约束为**弱不变量**：`ck_reservation_checkout_after_checkin` 实际表达为
`check_out > check_in OR (billing_type='DAY_USE' AND check_out = check_in)`，
因此「`billing_type=DAY_USE` 且 `check_out > check_in`」在数据库层**不被拒绝**。
该非法形态由服务层 `day_use.occupancy_dates()` 抛 `DayUseError` 拦截。
结论：业务行为正确（双层防护 + 应用层强校验），但数据库约束强度低于迁移说明文字描述。
**建议（未在本轮实施）**：后续可将约束改为
`(billing_type='NIGHT_STAY' AND check_out > check_in) OR (billing_type='DAY_USE' AND check_out = check_in)`，
需评估存量数据与 MySQL 表重建成本后单独提交。

## 四、TASK-02：手机号规范化统一（PASS，代码 SHA `5731e8a`）

### 4.1 问题与根因

改造前存在**两套并存实现**，且口径相反：

| 位置 | 原实现 | 效果 |
|---|---|---|
| `apps/guests/services.py::normalize_phone` | `re.sub(r"[^\d+]", "", ...)` | **保留 `+`**，不校验长度 |
| `apps/reservations/services.py::normalize_phone` | `"".join(ch ... if ch.isdigit())` + 6–20 位校验 | **只保留数字** |

同一号码（如 `+86 138 0000 1111`）因此产生两个不同哈希：

```
档案侧：HMAC(PII_KEY, "+8613800001111")
预订侧：HMAC(PII_KEY, "8613800001111")
```

三类业务后果：

1. **共享号码判定失真**（M-03 规则 2）：同一自然人前后台建档形态不同 → `shared_review_required` 不触发，重复档案产生。
2. **同手机号 PENDING 上限失效**（§6.4）：`Reservation.objects.filter(guest__phone_hash=gate_key)` 查不到另一种形态的存量单，暗示可超限下单。
3. **待确认锁行粒度分裂**（`PendingBookingGate.gate_key`）：并发仲裁按哈希分行，同一号码可绕过串行化。
4. 附带：公开预订限流电话维度按**原始字符串**指纹化（`rate_limit.fingerprint(phone)`），同一号码换写法即可各拿 3 次/10 分钟配额。

### 4.2 口径裁定（工程基线，变更需评审）

| 维度 | 裁定 | 理由 |
|---|---|---|
| 存储/哈希形态 | **纯数字**，不含 `+` | 预订/待确认锁行/账务检索历来按纯数字，向既有数据靠拢 |
| `+` 的角色 | 仅作可接受的输入分隔符 | 不进入规范形态，避免同一号码两套哈希 |
| 国际号码 | 保留国家码数字（`+86 138...` → `8613800001111`） | 剥离前缀可能把不同号码误并成同一人，属业务判断，不自动化 |
| 位数约束 | 6 ≤ 位数 ≤ 20 | 沿用预订侧既有规则，拦截明显残缺与超长输入 |
| 必填性 | 预订/入住必填；客人档案允许为空 | 由调用方选择 `require_phone` 或直接规范化，**不把业务允许性写进规范化函数** |
| 历史数据 | **不改写** | 见 §4.4 |

分层职责（`apps/core/phone.py`，无业务依赖、可被任意层引用）：

| 函数 | 职责 | 失败行为 |
|---|---|---|
| `normalize_phone(raw)` | 格式规范化：仅保留数字 | 不抛异常，空值返回 `""` |
| `digit_count` / `is_valid_phone` | 有效性判定 | 返回 bool/int |
| `validate_phone(raw)` | 校验并返回规范形态 | 抛 `ValueError("请输入有效联系电话。")`（与改造前文案、400 契约一致） |
| `require_phone(raw)` | 业务场景必填 | 空值或无效均抛 `ValueError` |
| `legacy_phone_variants(normalized)` | 历史形态枚举（`数字`、`+数字`） | 仅读侧使用 |
