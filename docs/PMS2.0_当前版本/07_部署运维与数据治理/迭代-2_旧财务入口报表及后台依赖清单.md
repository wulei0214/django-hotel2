## 0. 入口分类原则

| 分类 | 判定 | 处理原则 |
| --- | --- | --- |
| **Ⅰ 只读取旧财务数据** | 仅消费旧 Folio/FinanceRecord 财务凭证，不读取旧订单主记录或订单展示字段 | 可评估归档查询替代；确认所有调用方后才能退役 |
| **Ⅱ 读取旧订单 + 历史财务展示** | 读取旧订单主记录，并同时读取或展示旧收款、押金、Folio 等历史财务字段 | 必须先提供等价历史查询能力；归档查询通道和新旧对比就绪前不得下线 |
| **Ⅲ 只读取非财务订单/员工字段** | 仅消费订单状态、顾客/客房基础字段或员工身份字段，不读取历史财务字段 | 不得因财务退役而删除或下线，由订单域/员工域负责 |

**现行分类：E1/E2/E3/E4 → Ⅱ；E5 → Ⅲ；本清单当前没有确认的纯Ⅰ类现役入口。**

### 1.3 兼容跳转与新旧账单 API 的边界

## 2. 报表依赖

- ADR：apps/api/report_center.py:293 起，分子使用 LedgerEntry 的 ROOM_CHARGE 及其 REVERSAL 红字冲销，分母使用 RoomTypeInventory.sold；不是旧 FinanceRecord/Folio 口径。
- 收入报表：apps/api/report_center.py:393 起，使用 LedgerEntry 正数/负数凭证计算收入、支出、净额，并按物业结算币种拆分；负数合计属于账本资金变动口径，不应误称为损益口径。
- 首页仪表盘：apps/api/dashboard.py:1-100 使用 Reservation、Stay、Room、LedgerEntry、Payment、Refund、Guest、GuestMembership 等 PMS2 模型聚合；财务指标来自新账本。
- 结论：现役收入/ADR/首页财务指标已走 PMS2 新侧；历史旧财务数据展示仍存在于 E1-E4，不能据此推断旧历史记录已完成归档替代。
