# 迭代-2 旧财务入口、报表及后台依赖清单

> 阶段 A 交付物（依赖清单，修订版 2026-11-13：评审意见落实——入口三分类处理原则 + 外部调用确认前置）。基线 da571b0。每条带证据；"活跃"= 非 410 桩且已挂载路由（或 admin 注册）。

## 0. 入口三分类处理原则（评审要求：不得混淆"财务字段读取"与"整表读取"）

| 分类 | 判定 | 处理原则 |
| --- | --- | --- |
| **Ⅰ 只读取旧财务数据** | 端点/页面消费旧财务凭证/流水本身（E1 folio_api 读旧 Folio 聚合） | 财务退役对象：评估保留、切归档表或退役 |
| **Ⅱ 读取旧订单 + 历史财务展示** | 消费旧订单主记录并**同时**展示历史财务冗余字段（E2/E4） | **必须先提供等价历史查询能力**（归档查询通道就绪前不下线），再评估切换 |
| **Ⅲ 只读取非财务订单字段** | 仅消费订单业务字段（顾客/客房/状态），不触财务（E3/E5） | **不得因财务退役而删除或下线**（订单域管辖） |

**E1-E5 分类**：E1→Ⅰ；E2/E4→Ⅱ；E3/E5→Ⅲ。Accommodation **整表写面 = 0**（207a937 死代码清理后全仓零写调用）——Ⅱ/Ⅲ 类入口的保留不构成财务写风险。

## 0.1 外部调用确认（评审要求：D2 停止读取的前置步骤）

- D2 执行前必须完成：① 网关/访问日志检索（/folio/ 与 legacy 端点近期调用记录）；② 浏览器书签与外部系统接口排查（运维+业务方问询）；③ 结果登记 §1.1（folio_api 状态从"疑似孤立"改为"确认零调用"或"存在调用方 X"）；
- 未经外部调用确认，folio_api 保持原状，不退役不下线。
