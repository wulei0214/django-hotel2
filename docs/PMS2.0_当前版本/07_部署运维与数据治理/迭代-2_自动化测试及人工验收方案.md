# 迭代-2 自动化测试及人工验收方案

> 阶段 C/D/E 交付物（测试与验收设计）。原则：迁移/对账工具的每一层守卫都要有自动化测试先行；人工验收只做机器不能证明的事（抽凭、追溯演示、签署）。
> 本轮为**方案设计**，测试代码在阶段 D 实施时按 TDD 先行交付。

## 2. 人工验收清单（机器不能证明的部分）

### 2.1 阶段 C 收口（映射与对账）

- [ ] 财务负责人抽凭：从 C1 迁移清单随机抽 30 条，对照 legacy_reservations 页面历史原貌逐字段核对；

## 4. 硬性限制重申（阶段 D 实施时的红线）

1. 不删除旧表（D5 两步法单独审批前）；
2. 不批量迁移生产数据（先 dry-run 报告 → 负责人批准 → 分批执行）；
3. 不改变新账本写入规则（迁移凭证走既有 BillingService/凭证创建通道，不绕过 ImmutableLedgerEntryQuerySet）；
4. 不绕过财务审批与不可变约束（冲销 legacy_workflow 是既有合规通道，不是新建旁路）；
5. 全部迁移/对账代码走 TDD（§1 矩阵用例先行）+ 双库验证 + CI 门禁。
