## 二、操作步骤（全部为页面点击，无 API 直调）

1. `v12_fin` 登录 → 财务管理中心 → 检索预订号 → 「查看」打开账单抽屉；
2. 支付行「申请退款」→ 填写金额 `210.00`、原因 → 「提交退款申请」（`POST /api/v1/billing/refunds` 201）；
3. `v12_gm` 登录 → 同路径打开抽屉 → 出现「审批通过」→ 点击（`/refunds/{id}/approve`）；
4. `v12_fin` 再登录 → 出现「执行退款」→ 点击 → 弹窗要求渠道参考号（输入 `V12-TRANSFER-REF-0001`）→
   确认"已实际支付给住客" → **被服务端拒绝：退款申请人不能执行自己的退款**（截图存证）；
5. `v12_fin2` 登录 → 点击「执行退款」同意弹窗 → 执行成功（`/refunds/{id}/execute`）；
6. 刷新页面、重新检索并打开抽屉，复核状态。

## 四、本次实测确认的业务规则

- **申请人与执行人必须分离**：系统按 `requested_by` 拦截，页面禁用按钮并给出明确文案；
- **审批与执行分离**：`v12_fin` 无 `refund_approve`，无法自审；
- **重复提交不产生重复退款**：执行按钮点击后使用幂等键（`PMS2-REFUND-EXEC-*`），
  重复请求走重放路径；
- **失败不得伪造成功**：被拒时页面显示错误条，退款状态保持 `APPROVED`（DB 已核对）。

## 五、证据边界（如实登记）

| 事项 | 说明 |
|---|---|
| 被退款项的来源 | 住客 + 预订 + 入住单 + 一笔 210.00 CARD 收款由**服务层预置夹具**创建（`create_walk_in` + `BillingService.collect_payment`），**不是**浏览器操作。退款申请/审批/执行三步均为纯浏览器 |

| 无权限员工越权 | 本轮以"申请人执行自己的退款"一种边界取证；其余越权组合见权限矩阵（未在本轮浏览器重跑） |
