## 一、退役事实（代码侧）

`apps/api/front_desk.py::walk_in_create`（`apps/api/urls.py:177`）：

- 任意 `POST` 一律返回 `410 Gone`，**不区分**认证/权限/入参，不读取请求体，不做任何业务写入；
- 观察期随退役一并结束：**不再**记 `frontdesk.legacy_walk_in_called` 观测审计；
- 业务事实源 `apps.reservations.walkin.create_walk_in` 保留在服务层，仅由标准入口调用。

这意味着：**退役后旧入口不再产生任何内部观测事件**，因此"生产是否还有残留调用"
只能从**部署侧访问日志**（nginx/Apache/IIS/WAF 等）判断，不能从应用审计表反推。

## 二、统计工具（本轮新增）

`scripts/walkin_410_stats.py`

| 能力 | 说明 |
|---|---|
| 输入格式 | 常见 `combined/common` 访问日志（nginx/Apache/IIS 导出）；单行 JSON（`{"request": "...", "status": 410}`） |
| 目录模式 | `--pattern "access*.log"` 递归匹配 |
| 时间过滤 | `--date 20/Nov/2026`（日志时间列子串） |
| 输出 | `legacy_hits` / `standard_hits` / `legacy_by_status` / `legacy_by_day` / `legacy_by_ua` / `distinct_sources` |
| 隐私 | **不输出客户端 IP**，仅输出 SHA-256 前 8 位的来源去重计数；不输出 cookie/Authorization/请求体 |
| 退出码 | `0` 统计完成；`2` 无可解析日志行（**拒绝静默当作"零残留调用"**） |

## 四、真实环境观察结果

### 4.1 生产环境：无日志 → 无法判定

本仓库 `logs/` 下**没有任何 Web 服务器访问日志**，只有应用侧日志：

| 文件 | 性质 | 能否用于 410 统计 |
|---|---|---|
| `logs/request.log` | Django 应用日志，仅 WARNING 及以上（异常/4xx/5xx 摘要） | 仅能作为**下界补充**，不含全部成功/正常请求，也不含部署侧真实来源 |
| `logs/audit.log` | 业务审计日志 | 否（退役后旧入口不再写审计） |
| 其余 `*.log` | 定时任务/维护任务输出 | 否 |

因此：

- **生产环境旧入口命中次数：未取得**（无生产访问日志，无生产环境访问权）；
- 按任务书要求，本项只能标记为 **“生产观察待完成”**，**不得**写"生产残留为零"。

## 六、遗留与风险

1. **生产观察未完成（阻塞项）**：需部署侧提供退役时间点之后（≥ 2026-11-19）的
   nginx/Apache/IIS 访问日志，跑一次
   `python scripts/walkin_410_stats.py <日志目录> --pattern "access*.log" --date 20/Nov/2026`，
   把 `legacy_hits` 与 `legacy_by_ua` 填入本报告 §四，才能关闭本任务。
2. **应用日志只能当下界**：`logs/request.log` 仅记录 WARNING 及以上，正常请求不落盘，
   用它统计会系统性低估命中次数；只能用于"确实有人在调旧入口"的存在性判断。
3. **退役后无内部观测**：旧入口不再写 `frontdesk.legacy_walk_in_called` 审计，
   若后续需要长期观察，只能在**网关/反向代理层**加计数（应用层不再具备该能力）。
   这是退役决策的既定代价，需在运维文档中写明，避免后续误以为"没审计=没调用"。
4. **`logs/` 目录混放产物**：`logs/` 下同时存在验收数据库快照（`hotel_acceptance.sqlite3`、
   `pii_drill_scratch.sqlite`）与 SQL 备份（`pii_drill_mysql_backup.sql`）。这些不属于日志，
   但会让"扫描 `logs/` 目录"的工具误读。本工具已按行格式过滤（不可解析即跳过）并
   以退出码 2 拒绝空样本；仍建议后续把这些文件迁出 `logs/`。
