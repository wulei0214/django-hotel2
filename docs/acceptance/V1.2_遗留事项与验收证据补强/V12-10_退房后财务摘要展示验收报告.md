## 一、问题描述与判定标准

退房时账单被置 `Folio.Status.CLOSED`。既有聚合契约（D-R4-08）规定
`folio_summary` 的 `charges / credits / balance` **只统计 OPEN 账单**（"当前应收"），
因此退房后三个数字同时归零。页面若只有这三个数字，用户会把"归零"读成
"历史账单、收款、退款记录被抹掉了"。

判定标准（任务书 §V12-10）：

1. 当前未结应收为 0 时，页面必须**明确说明历史账务仍在**；
2. **不得**把 CLOSED Folio 重新纳入当前应收聚合（不得为"看起来正常"而破坏聚合契约）；
3. 历史明细入口不得因关账而消失。

历史口径实现要点（`apps/api/front_desk.py`）：

```python
if folio.status != Folio.Status.OPEN:
    if folio.currency == summary["currency"]:
        closed_entries = list(folio.entries.all())
        summary["closed_folio_count"] += 1
        summary["closed_charges"] += sum((e.amount for e in closed_entries if e.amount > 0), Decimal("0.00"))
        summary["closed_credits"] += sum((-e.amount for e in closed_entries if e.amount < 0), Decimal("0.00"))
    continue          # ← CLOSED 仍然 continue，不进入当前应收
```

即：**同一份摘要里并存两套口径**——`charges/credits/balance` 是"当前未结应收"，
`closed_*` 是"已结账单的历史累计"，互不覆盖。

## 七、遗留与风险

1. **两套口径并存需要文档说明**：`reservations/<no>` 的 `folio_summary` 是"当前应收"，
   `folios/<no>` 的 `summary` 是"账单全量"。本轮只在前端标签上做了区分，
   **API 响应字段名未区分**（仍叫 `charges/credits/balance`）。后续若新增调用方，
   必须在接口文档中显式标注，否则会再次出现口径混读。
2. **已结账单仍提供「申请退款」入口**：本夹具为已退房已关账订单，抽屉里"支付/押金"
   行仍有「申请退款」按钮。退款属事后业务，是否放行由 `billing.refund_request`
   权限与既有审批链决定，不在 V12-10 范围，但建议在 V12-04 后续复盘中确认
   "已关账账单发起退款"的业务口径是否需额外审批层级。
3. **未覆盖多币种**：`closed_*` 只在 `folio.currency == summary["currency"]` 时累加，
   多币种账单仍由既有 `currency_mismatch` 机制处理；本轮无多币种样本，未取证。
