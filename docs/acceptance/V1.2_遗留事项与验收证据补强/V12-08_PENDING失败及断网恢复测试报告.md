## 一、测试前置数据

一笔真实入住单（服务层夹具创建：住客 + 预订 + 排房 + 入住 + 30% 现金押金），
账单仅押金 `-90.00`，应收 `210.00`，用于前台"登记线下收款"。

## 二、场景与实测结果

| # | 场景 | 操作 | 实测 |
|---|---|---|---|
| A | 收款请求失败（模拟网络中断） | 通过路由拦截把 `POST /api/v1/front-desk/reservations/*/payments` **中止**，页面填 50.00 + CARD 后提交 | 拦截生效 **1 次**；页面提示 **"网络连接失败，请检查服务器后重试。"**；**无任何成功文案**，DB 无新增支付 |
| B | 网络恢复后重试 | 解除拦截，原表单再次提交 | 提示 **"已登记本次实收款"**；DB 新增 1 笔 50.00 CARD 支付 + 1 条 `PAYMENT` 凭证 |
| B' | 重复提交（不改输入 → 复用幂等键） | 再次点击同一提交按钮 | 仍提示"已登记本次实收款"，**未产生第 2 笔支付**（同一次执行内支付数恒为 1） |
| C1 | 断网 + 手动刷新 | `context.set_offline(True)` 后点击「刷新数据」 | 提示 **"网络连接失败，请检查服务器后重试。"**，列表保持上一份真实数据，未显示虚假成功 |
| C2 | 断网 + 刷新页面 | 断网状态 `page.reload()` | 浏览器错误页（`Error`），未出现"操作成功"残留态 |
| C3 | 恢复网络后重新查询 | 恢复在线 → 重新进入 `/checkin/` → 检索订单 | 页面重新从服务端取数，订单可见、抽屉可打开；账单明细显示实际支付记录 |

## 三、数据库核对

| 对象（folio 29） | 值 |
|---|---|
| `billing_payment` | 32 `DEPOSIT 90.00 CASH`；33 `50.00 CARD`；34 `50.00 CARD`（两次独立执行各 1 笔） |
| `billing_ledgerentry` | 43 `DEPOSIT -90.00`；44 `PAYMENT -50.00`；45 `PAYMENT -50.00` |
| 中断请求的痕迹 | **0 笔**（A 场景被中止的请求未落库；页面也未显示成功） |

口径说明：本脚本执行了两轮（首轮在 C 阶段因抽屉遮挡中断，修正交互后完整重跑），
每轮"1 次中断 + 2 次提交"最终只产生 **1 笔**支付，因此 2 轮 = 2 笔，
即**中断不产生写入、同轮重复提交不产生重复收款**。

## 四、与任务书要求的逐项对照

| 要求 | 状态 | 说明 |
|---|---|---|
| 支付/押金请求失败 → 订单状态保持 | PASS | 失败后账单/订单状态未变（DB 核对） |
| 不产生孤儿支付凭证 | PASS | 中止请求 0 条 Payment / 0 条 LedgerEntry |
| 重复提交不重复收款 | PASS | 同轮复用幂等键，提交 2 次仍 1 笔 |
| 断网 → 刷新 → 恢复 → 重新查询 | PASS | C1/C2/C3 三步均有截图 |
| 不保留本地虚假成功状态 | PASS | 断网刷新后为浏览器错误页，恢复后以服务端数据为准 |
| 支付超时 / 渠道失败 / 金额校验失败 | **未在本轮浏览器取证** | 超时与渠道失败属支付渠道回调面（`apps/billing` 支付意图/回调幂等用例在 V1.1 矩阵覆盖）；金额校验（超应收 409）有既有自动化用例，本轮未重跑 |
| 押金（DEPOSIT）独立失败路径 | **PARTIAL** | 本轮验证的是"登记收款"接口；押金表单走同一 `collect_payment` 服务与同一前端 postApi 失败处理，但未单独制造押金失败 |

## 五、遗留与风险

1. **服务端错误与网络错误文案未区分**：中止请求与真实断网都显示同一句
   "网络连接失败，请检查服务器后重试。"，对前台排查不利（无法判断是网络问题还是
   服务端 5xx）。属体验问题，未在本轮修改（不在 V12-08 代码范围）。
2. **PENDING 订单 12 项矩阵未整体重跑**：本轮只补强"失败/断网"三条，其余项沿用
   `R6-05` 自动化证据，二者不得混计。

## 六、结论

前台收款失败、重试幂等、断网恢复三类场景均在真实浏览器内完成并核对到数据库，
未出现"页面成功但库里没有"或"中断仍落库"的伪成功。**本任务判 PASS**（限定于上述场景），
超时/渠道失败/押金独立路径按 §四 登记为未取证。
