## 三、P0 专项结论

### V12-01 资金（PASS）

- **整改前事实与任务书描述不同**：不是"少计一晚"，而是**整条路径不存在**——模型
  `CheckConstraint(check_out > check_in)`、`create_reservation`、`stay_dates` 三处硬拒，
  所以既无历史 day-use 数据，也不存在"用退款负债掩盖收入缺口"的存量问题。
- **整改**：显式 `billing_type`（不靠日期反推）+ `DayUsePolicy` 政策定价（缺水 fail-closed，
  不回落过夜价、不按 0 元）+ 入住即确认 `ROOM_CHARGE`（`day-use:{stay.pk}` 幂等）+ 超时独立
  `ADJUSTMENT`（`day-use-overtime:{stay.pk}`）+ 退房只补差额（实测差额 0）。
- **未按任务书禁止项操作**：没有把不足一晚强按一晚收费，没有用退款负债或报表调整掩盖，
  过夜计费未改动（`test_night_stay_with_equal_dates_is_still_rejected` 等守卫生效）。
- **浏览器闭环**：服务层建单（前台 UI 无日租入口，见 V12-01 §六）→ 浏览器点「办理退房」→
  账单 `CLOSED`、房态 `VACANT/DIRTY`、明细仍只有 1 条日租房费。

### V12-02 安全（BLOCKED —— 本轮唯一未关闭的 P0）

- 任务书要求"必须证明旧口令不能认证或账户已锁定/删除"，并明确**扫描器 0 命中、文档脱敏、
  代码无明文均不能单独作为关闭依据**。本轮三条独立路径全部被权限挡住：

| 取证路径 | 结果 | 说明 |
|---|---|---|
| `mysql -h localhost -u hotelhotel` 用旧口令认证 | `ERROR 1045 Access denied` | **不能**区分"账户不存在"与"口令不同"，故不构成证明 |
| 直接查 `mysql.user` 的 `plugin/authentication_string/account_locked` | `ERROR 1142`（无 SELECT 权限） | 无 DBA 权限 |
| `information_schema.USER_PRIVILEGES` | 只有 `'hotelhotel'@'127.0.0.1'` | 该视图不列无权限账户，**不能证明 `@localhost` 不存在** |

- 因此本项**不关闭**。关闭条件（交给 DBA/运维，一条命令即可）：
  `SELECT user, host, plugin, account_locked, authentication_string FROM mysql.user WHERE user='hotelhotel';`
  若 `@localhost` 存在 → `ALTER USER 'hotelhotel'@'localhost' ACCOUNT LOCK;`（或 `DROP USER`）
  并回填结果；若不存在 → 贴出该查询的空结果集。

## 九、结论

本轮把 V1.2 十项遗留中可关闭的部分做实（含两项 P0 之一的资金项），并用真实浏览器而非
自动化结果补强了退款、收款失败/断网、日租退房、退房后摘要五条链路；同时登记并修复了
9 个真实缺陷、把凭据扫描与排房冲突并发两道门禁换成不会空转的实现。

但 **V12-02（P0，安全）仍未关闭**：现有账号无权读取 `mysql.user`，只能用 `ERROR 1045`
间接观察，而该错误无法区分"账户不存在"与"口令不同"，按任务书纪律不能据此关闭。

**故本轮总体判 NO-GO（不得宣布全部通过）**：P0 未全关闭 + 三类证据缺口（写操作浏览器、
生产日志、连接容量）在册。待 §八 L1 关闭并可复算后，方可重新申请整体验收。
