## 2. 修改内容

### 2.1 整改项一：清理计划绑定（`retention.py` L216-247）

正式执行前新增四重一致性校验，任一不满足即拒绝：

| 校验 | 实现 | 对应测试 |
|---|---|---|
| `entity_type` 必须是 `RetentionExecution` | L217-218 | PB-09 |
| 审批绑定的计划必须**真实存在** | L219-225 | PB-09 |
| 计划与本次执行**同物业** | L226-227 | PB-03 |
| 计划必须是 **dry-run** | L228-229 | PB-05 |
| 计划**策略一致** | L230-231 | PB-04 |
| 计划**基准日一致** | L232-233 | PB-05 |
| 计划**未被执行/终止**（禁止重复使用） | L235-242 | PB-06/07/08 |
| 若传入 `execution=`，必须**就是**审批绑定的那条 | L244-249 | PB-02 |

> 关键设计：绑定成立后，执行记录**复用该计划的策略与基准日**（L257-260），保证「审批 A 就只能执行 A」。

### 2.2 整改项二：执行权限独立校验（`retention.py` L251-260）

```python
if not AuthorizationService.has_permission(
    operator, property_obj, "guests.retention_execute"
):
    raise PermissionDenied("...审批通过不能替代执行权限。")
if approval.requested_by_id == operator.pk:
    raise ValueError("执行人不得为审批申请人（职责分离）。")
```

- 走 `AuthorizationService`（真实岗位链 `StaffRoleAssignment → group.permissions`），非仅装饰器；
- 位于**服务层正式执行路径**，任何调用方（含直接调用 Service）都无法绕过 → 由 EP-14 验证。

### 2.3 其他必要修改及原因

| 修改 | 原因 |
|---|---|
| `_safe_int()` 辅助（L57-66） | 审批 `entity_id` 为 CharField，绑定校验需安全转 int；非法值视为「绑定不成立」 |
| `test_retention.py` 的 `_make_approval` 增加 `plan` 参数 | 原夹具用 `entity_id="batch-test"`（非真实计划），绑定校验后必然被拒——属**测试适配**，非放宽 |
| `test_retention.py::test_formal_execution_via_real_path_anonymizes` 改为先 dry-run 再绑定 | 同上，使测试符合新契约 |

**未修改**：`registry.py`、`approval_registry.py`、任何迁移、任何权限码（遵守 §8.2「不新增重复权限码、不新增未经批准的迁移」）。
