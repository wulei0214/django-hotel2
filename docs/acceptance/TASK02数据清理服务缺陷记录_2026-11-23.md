## 1. 缺陷 1：正式执行路径必然崩溃（高）

### 1.1 现象

受控实验（`.work/audit_t02/verify_defect.py` 实验 1/2）：

```
实验 1：新建实例 pk = None
  结果：抛 ValueError: Cannot force an update in save() with no primary key.

实验 2：调用 plan_retention_cleanup(dry_run=False)
  调用前 full_name = '验证客人'
  调用抛 ValueError: Cannot force an update in save() with no primary key.
  调用后 full_name = '验证客人'（未变更说明匿名化未发生）
```

### 1.2 根因

`retention.py:114-171`：

```python
def plan_retention_cleanup(*, property_obj, policy, as_of, operator, dry_run=True):
    ...
    exec_record = RetentionExecution(          # L121 仅构造，未 save()
        property=property_obj, ...
    )
    candidates = candidate_guests(...)
    exec_record.candidate_count = candidates.count()

    if dry_run:
        ...
        exec_record.save()                      # L152 dry-run 分支有 save()
        ...
        return exec_record, to_process

    # 正式执行
    exec_record.execution_status = RetentionExecution.ExecutionStatus.EXECUTING
    exec_record.save(update_fields=("execution_status",))   # L171 ← 此时 pk is None
```

`dry_run=False` 分支**从未先 `save()` 建立主键**，却用 `update_fields` 保存。Django 对无 pk 的实例使用 `update_fields` 会直接抛
`ValueError: Cannot force an update in save() with no primary key.`

### 1.3 影响

| 维度 | 评估 |
|---|---|
| 功能可用性 | **正式清理功能 100% 不可用**（非"部分"） |
| 数据安全 | 反而**未造成**误删（崩溃发生在匿名化之前，guest 未被改动——已验证 `full_name` 保持不变） |
| 是否静默 | **否**，抛异常，调用方会感知 |
| 严重性 | **高**（核心功能不可用），但**无数据破坏风险** |

### 1.4 修复建议（供 TASK-02 责任人参考）

在 `dry_run` 分支之后、进入正式执行前补齐落库：

```python
    # 正式执行：先落库建立 pk（execution_status=EXECUTING）
    exec_record.execution_status = RetentionExecution.ExecutionStatus.EXECUTING
    exec_record.save()          # ← 去掉 update_fields，或先 save() 一次
    for guest in to_process:
        ...
```

或改为 `exec_record.save()` 后再 `save(update_fields=...)`。

## 2. 缺陷 2：审批校验未实现（高）

### 2.1 现象

`ACTION_RETENTION_EXECUTE` 在 `retention.py` 中**出现仅 1 次**（第 36 行定义），**无任何引用**：

```
L36: ACTION_RETENTION_EXECUTE = "privacy.retention_execute"
```

`plan_retention_cleanup` 函数体内**不含** `ApprovalRecord` / `APPROVED` / `ACTION_RETENTION_EXECUTE` 任何校验（脚本已逐行检查）。

### 2.2 与声明矛盾

| 位置 | 声明 |
|---|---|
| 模块 docstring 第 16-17 行 | 「正式执行必须携带 APPROVED 审批引用且申请人≠审批人（由 ApprovalRecord 保证）」 |
| 函数 docstring 第 118 行 | 「正式执行必须已通过 plan 之外的审批链（approval_reference 必填）」 |
| **实现** | **无任何校验** |

`RetentionExecution.approval_reference` 字段虽存在，但**正式执行路径不读取、不校验它**。

### 2.3 影响

| 维度 | 评估 |
|---|---|
| 安全边界 | 若缺陷 1 修复后此缺陷仍在，则**任何调用方可直接 `dry_run=False` 触发不可逆匿名化**，无需审批 |
| 职责分离 | 「申请人≠审批人」的 SoD 约束完全依赖调用方自觉 |
| 严重性 | **高**（不可逆操作的审批门缺失） |
| 当前实际风险 | **低**——因缺陷 1 使该路径崩溃，尚不可达（但修复缺陷 1 后会立即暴露） |

### 2.4 修复建议

在正式执行入口强制校验：

```python
    if not dry_run:
        if not approval_reference:
            raise ValueError("正式执行必须提供已批准的审批记录引用。")
        approval = ApprovalRecord.objects.filter(
            pk=approval_reference,
            property=property_obj,
            action_code=ACTION_RETENTION_EXECUTE,
            status=ApprovalRecord.Status.APPROVED,
        ).first()
        if approval is None:
            raise ValueError("审批记录不存在、未通过或不属于本物业。")
        if approval.requested_by_id == operator.pk:
            raise ValueError("申请人不得自批（职责分离）。")
```

> 注意：当前 `plan_retention_cleanup` **签名中没有 `approval_reference` 参数**，需一并补入。

## 3. 测试为何未发现（测试有效性缺陷）

`test_retention.py:285-316` `test_execution_anonymizes_guest`：

```python
def test_execution_anonymizes_guest(self):
    guest = self._make_guest("正式执行", days_ago=400, phone_cipher="QUJD")
    execution, to_process = plan_retention_cleanup(..., dry_run=True)   # ← dry_run=True
    self.assertEqual(len(to_process), 1)
    execution.approval_reference = "AR-TEST-1"
    execution.dry_run = False
    execution.candidate_count = 1
    execution.save()
    _exec2, processed = plan_retention_cleanup(..., dry_run=True)       # ← 又一次 dry_run=True
    anonymize_guest(guest)                                             # ← 手工直接调
    ...
```

**问题**：
1. 两次调用都是 `dry_run=True`；
2. 真正执行匿名化的是**手工调用** `anonymize_guest(guest)`；
3. 因此 **`plan_retention_cleanup(dry_run=False)` 这条正式路径从未被测试**。

第 295 行注释也承认：「正式执行（测试环境直接调；**审批链在 API 层测**）」——但 `apps/api/` 中同样未找到调用该函数的 API 端点（`git grep plan_retention_cleanup` 仅命中 `retention.py` 与 `test_retention.py`）。

`test_formal_execution_requires_approval_reference`（第 326 行）只测了 `full_clean()` 会因 `approval_reference` 缺失抛 `ValidationError`——这是**模型层**校验，**不是执行路径**校验。
