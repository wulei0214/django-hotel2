## 三、API 级越权探测（浏览器会话内发起）

| 探测 | 结果 | 服务端响应 |
| --- | --- | --- |
| front → POST /api/v1/night-audit/run | 403 | PERMISSION_DENIED「当前岗位没有该项夜审权限。」 |
| front → GET /api/v1/billing/ledger | 403 | PERMISSION_DENIED「员工任职或财务权限验证失败，无法访问财务中心。」 |
| front → GET /api/v1/staff | 403 | PERMISSION_DENIED「缺少员工管理权限。」 |
| housekeeping → GET /api/v1/billing/ledger | 403 | 同上财务拒绝文案 |
| housekeeping → POST /api/v1/billing/shifts/open | 403 | PERMISSION_DENIED「当前岗位没有收银班次管理权限。」 |
| housekeeping → GET /api/v1/staff | 403 | PERMISSION_DENIED「缺少员工管理权限。」 |

负向结论：页面 403 与 API 403 双层一致，构造 URL 与直接请求不能绕过权限，无越权路径发现。

## 五、高风险动作审批/原因码/审计

- 退款三方 SoD：申请人≠审批人≠执行人，违反即 400/403（链路 B 实证）。
- 营业日重开双人审批：duty 申请 → owner 批准，申请人≠审批人（链路 F approval 11 实证）。
- 权限矩阵变更：并发双批准恰一个胜出、审计恰一次（`apps/identity/test_permission_approval_concurrent.py`，R5 报告 §二#9/#10）。
- 敏感揭示：guest_document_reveal/guest_phone_reveal 独立权限 + 原因码 + AuditEvent。

## 六、任职变更权限失效

- 员工生命周期服务创建/授权/终止：test_finance2（E2026-FIN2）grant/terminate 全程审计留痕（链路 E）。
- 激活成员并发唯一性：`ActiveMembershipUniquenessConcurrencyTests` 恰一个生效；终止成员后工号序列延续（`test_mysql_concurrency.py`）。
- 离职/停职后任职状态变更即收回授权（registry 按 active membership 解析权限）。

## 七、结论

九岗位权限矩阵逐岗验证允许操作与禁止操作，前端菜单/按钮、页面 URL、API、构造请求、敏感字段、高风险审批、任职失效七层一致，未仅以 HTTP 403 作为完整验收。独立验收 G14 确认通过。
