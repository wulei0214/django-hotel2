## 一、扫描方法与判定规则

**输入全部取自 git blob（`<sha>:<path>`），不读工作区**，因此并行会话的未提交文件不会污染结果。

1. **路由清单**：解析 `hotel/urls.py` 的 AST，取出所有 `path()/re_path()` 且 view 以 `views.` 开头的条目 —— 即"旧页面路由"（不含 `apps/` 下的新 API 与 `platform/`、`reserve/` 等新页面路由）。
2. **视图行为**：对每个 view 做 AST 遍历，采集：渲染的模板、是否出现字面 `410`、`objects` ORM 使用、写方法调用（`save/create/update/delete/bulk_*/get_or_create/update_or_create`）、服务层调用、装饰器（权限门禁）、重定向。
3. **引用扫描**：对 522 个语料文件（tests=123 / code=324 / templates=37 / static=35）做字面量边界检索，得到模板/静态/代码/测试四类引用点。
4. **测试覆盖实测**：另用"带引号的完整路径"在 123 个测试文件中检索（重扫脚本的边界正则会漏掉 `"/show_client/"` 这类前导斜杠写法，故补一轮）。
5. **替代入口**：取自 `apps/api/pages.py` 的 `MANAGEMENT_CENTERS` 注册表（11 个中心）。

**处置标记只允许五种**：`KEEP / REDIRECT / 410 / MIGRATE / DELETE`。
