## 5. 体积根因：日志被「轮转失败」污染（可修缺陷）

对 `test-mysql-wb-round30-final.log`（19.55 MB / 160,283 行）逐行分类：

| 行类型 | 行数 | 占比 |
|---|---|---|
| `--- Logging error ---` 及随后的 `PermissionError` 栈、`Arguments/Call/Message/argv/command_line` 等调试块 | 113,448 | **70.8%** |
| 真实测试输出 | 46,767 | 29.2% |

同文件内：`--- Logging error ---` 1,340 次、`PermissionError:` 1,850 行、`doRollover` 3,700 行。round28–round30 的 8 份大日志合计 **10,696 次**轮转失败。

根因（`hotel/settings.py:252-267`）：`audit_file` / `request_file` 均用 `RotatingFileHandler(maxBytes=1MB, backupCount=5)` 写 `logs/`。全量回归期间 `hotel.audit` 以 INFO 级持续写入，每次越过 1 MB 触发 `doRollover()` → 重命名 `audit.log`→`audit.log.1`，而该文件正被另一进程（runserver/waitress）或另一 handler 持有 → Windows 下 `PermissionError` → 标准 `logging` 把完整栈打到 stderr，被 `2>&1` 收进日志。

即：**日志体积的 70% 不是测试信息，是一个可修的日志配置缺陷在放大输出**。8 份文件里约 142 MB 是这条路径产生的噪声。

修复方向（本轮不改，`hotel/settings.py` 正被并行会话修改）：

1. 测试环境禁用文件 handler（`DJANGO_ENV=test` 时仅保留 console），或改用 `delay=True`；
2. 生产用 `TimedRotatingFileHandler` 或由外部 logrotate 接管，避免进程内重命名；
3. 给 `queue.QueueHandler` 或 `errors="backslashreplace"` 兜底，禁止 `handleError` 把栈写进业务输出。

预估收益：同样的全量回归，日志从 19.55 MB 降到 **≈5.7 MB**（仅去噪），再关闭 `-v 2` 级逐测试输出可降到 **<1 MB**。

## 7. 向前治理规则（建议，待批准）

1. **入库阈值**：单个证据文件 >512 KB 时，须同时提交摘要段（`Ran N / 结论 / 失败项 / 耗时 / 命令`），否则 CI 拒绝。
2. **摘要化替代**：全量回归日志只保留摘要 + 失败用例段落；完整输出留在本地 `logs/` 或外部归档，不入库。
3. **禁止 `2>&1` 直收**：跑测试时先修日志 handler（§5），或把 stderr 单独重定向，避免把 `logging` 内部错误写进验收证据。
4. **重复截图自查**：同一目录内前后状态截图哈希相同时，只留一张并在报告里注明"前后视觉一致"。
5. **失败证据永不留删**：`FAILED` 轮次日志优先级最高（不可再生），任何归档动作都必须先确认不在本清单 §2 第 14/16/17 行范围内。
