## 四、独立复现发现的指南缺陷（2 项，需修订）

### 缺陷 1（实质，建议必改）：`mysqldump` 缺 `--no-tablespaces`

- **现象**：按 §六 原文执行 `mysqldump ... hotel --result-file=...`，命令**退出码 0 且备份文件完整生成**（1,259,210 B），但 stderr 报错：
  `mysqldump: Error: 'Access denied; you need (at least one of) the PROCESS privilege(s) for this operation' when trying to dump tablespaces`
- **根因**：MySQL 8 的 `mysqldump` 默认尝试导出 tablespace 元数据，需 `PROCESS` 权限；应用账号 `hotelhotel` 未获授（且不应为备份而扩权）。
- **影响**：备份**实际成功**，但报错会让人误判失败；在自动化脚本中若以 stderr 非空判定失败，会导致备份链路被误标为故障。
- **实测修复**：加 `--no-tablespaces` 后 stderr 干净、退出码 0、文件大小完全一致（1,259,210 B）。
- **建议修订**：§六 备份命令改为
  ```bash
  mysqldump -h 127.0.0.1 -u<user> --no-tablespaces hotel > backups/hotel-YYYYMMDD.sql
  ```
  并在 §七 常见问题表新增一行：「mysqldump 报 PROCESS privilege → 加 `--no-tablespaces`（应用账号不应为此扩权）」。

### 缺陷 2（小，建议补）：恢复命令的 shell 重定向口径

- **现象**：§六 恢复命令写 `mysql ... hotel < backups/x.sql`，在 **PowerShell** 下 `<` 不是输入重定向运算符（会报 ParserError）。指南 §七 虽已提示 PowerShell 拆参问题（`-h127.0.0.1`），但未覆盖 `<` 重定向。
- **实测修复**：`cmd /c "mysql -h 127.0.0.1 -u <user> test_hotel < ""<dump>""` 可正常执行（本次恢复即用此法）。
- **建议修订**：§六 恢复命令补注「PowerShell 无 `<` 输入重定向，需 `cmd /c` 包裹或改用 `Get-Content x.sql | mysql ...`」。
