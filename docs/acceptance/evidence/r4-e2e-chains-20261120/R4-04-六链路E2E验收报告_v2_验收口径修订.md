## 一、验收方式四级口径定义

| 口径 | 定义 |
|---|---|
| **B（纯浏览器）** | 该步骤的触发、输入、提交全部经由真实页面控件完成（坐标点击/键入/表单提交），页面状态变化为操作结果 |
| **B+V（浏览器页面取证）** | 页面渲染、权限显隐、状态展示经浏览器验证并截图；该步骤不含写操作或写操作由其他口径完成 |
| **A（API 辅助完成）** | 写操作经与服务端同一端点/同域服务完成（curl/会话化脚本），原因是 IAB 点击投递限制或 window.prompt 无法自动化；页面取证仍由浏览器完成 |
| **S（环境准备 API）** | 非测试目标的准备动作（开班、账号切换等），明确计入 setup，不计入通过项 |

## 三、浏览器限制与应用缺陷的区分依据（链路 B 判定记录）

1. **现象**：billing_center 表格行"发起退款申请"按钮——坐标点击命中（elementFromPoint 返回 BUTTON 自身）、监听器源码无异常、同页"刷新"按钮可响应，但行按钮 4+ 次尝试均无效果；frontdesk 页"开班"按钮 handler 使用 window.prompt，IAB 运行时瞬时消隐 prompt 致静默返回。
2. **对照**：同一会话内 30+ 个页面控件点击成功（登录、页签、预订、支付、入住、退房、清洁、夜审、放行），失败集中于：window.prompt 型 handler 与个别表格行按钮。
3. **结论**：运行时合成事件投递限制（非确定性），非应用缺陷。判据：`elementFromPoint` 命中 + handler 源码审查无早退分支 + 页面无 JS 错误可见表现 + 同类控件可触发。
4. **处置**：写操作走同端点/同服务 API 路径完成并在本报告如实标注 A；B/A 口径不允许互换表述。
