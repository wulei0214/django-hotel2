## 1. 8 项缺项与任务书归纳的对应关系

任务书 §十三 列出 8 类生产待办。与仓库权威编号逐项映射如下（**任务书归纳 → 仓库权威编号**）：

|---|---|---|---|
| ① 正式服务器和部署环境 | **PROD-01** | 生产服务器未购买 | 一致 |
| ② DBA 及生产数据库资源 | **PROD-06**（+ PROD-03 依赖） | 生产数据库特权操作（V13-01 孪生账户取证） | 一致（DBA 资源同时是 PROD-03 前置） |
| ③ 支付渠道正式接入 | **PROD-05** | 真实支付渠道/银行/供应商联调 | 一致 |
| ④ 生产密钥及密钥轮换 | **PROD-02** | 生产环境密钥托管与轮换（含 PII 独立密钥） | 一致 |
| ⑤ 生产备份和恢复演练 | **PROD-03** | 真实生产备份恢复演练 | 一致 |

| ⑦ 监控、告警和日志平台 | **PROD-07** | 生产监控告警与灾备演练 | 一致 |
| ⑧ 生产环境综合验收及相关外部依赖 | **PROD-08** | MySQL 生产连接容量与池化验证（V13-04） | **部分不一致**（见 §1.1） |

### 1.1 唯一需注意的差异（不擅自改号）

- 任务书第 ⑧ 项是「生产环境综合验收及外部依赖」这一**概括性**条目。
- 仓库 **PROD-08** 是具体的「MySQL 生产连接容量与池化验证（V13-04）」。
- 二者不是同一事物：仓库的「综合验收」分散体现在 PROD-01~07 各自验收通过后的**整体签署**中，并未单列为 PROD-09。
- **处置**：遵守任务书「以仓库原始编号和定义为准，不能擅自合并或改号」→ **保留 PROD-01~08 原编号与原定义**，将「综合生产验收」登记为**依赖这 8 项全部完成后的聚合门禁**（§3），不新增 PROD 编号。

## 4. 状态保护规则（防伪造、防误改）

1. **禁止改标**：不得将 PROD-01~08 任一项改为「已完成」「PASS」，除非 §2 的「验收标准」在真实生产环境实测通过并附证据。
2. **禁止替代**：
   - 本地 MySQL 测试 **≠** 生产数据库验收（PROD-06/08）；
   - 本地备份恢复 **≠** 生产备份恢复演练（PROD-03）；
   - mock 支付通道 **≠** 真实渠道联调（PROD-05）；
   - 单进程本地 Redis **≠** 生产多 worker（PROD-04）。
3. **禁止阻塞本地开发**：本 8 项**不进入** PMS 2.0/PMS 3.0 本地开发的完成率与门禁判定；仅在生产上线判定时计入。
4. **证据归档**：任一项验收通过后，证据须入 `docs/acceptance/evidence/`，绑定 SHA、环境、命令与结果。
5. **编号保护**：PROD-01~08 编号与名称**冻结**；新增生产事项须由负责人批准后另编号（不得复用、不得合并既有编号）。
