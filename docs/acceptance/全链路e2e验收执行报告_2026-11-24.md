## 3. 三项失败的根因（同源，非产品缺陷）

### 3.1 B13：旧 walk-in 端点已按裁定退役为 410

**脚本断言**（`e2e_full_chain.py:803-821`）：

```python
# 双端点并存：旧 /walk-in（DEC-WALKIN-01）仍可用，且走同一服务层事实源
code, d = api(front, "POST", "/api/v1/front-desk/walk-in", ...)
step("B13 walk-in 旧端点并存 201（双端点同一服务层事实源）",
     code == 201 and walkin2_no and (d.get("data") or {}).get("stay_id"), ...)
```

**实际产品行为**（`apps/api/front_desk.py:1992-2018`）：

```python
def walk_in_create(request):
    """POST /api/v1/front-desk/walk-in 已按裁定下线，恒返 410 Gone（R2-04、DEC-WI-01）。
    ...
    业务事实源 apps.reservations.walkin.create_walk_in 仍在服务层，仅供
    walk_ins_create（/front-desk/walk-ins）使用；本路由仅留 410 载体。
    """
    return _response({"error": {"code": "GONE", ...}}, 410)
```

**哪个对？** 产品行为正确。`DEC-WI-01` 是已生效裁定，且有多处落档：
- `Walk-in双端点统一与观察期审计R2实施记录_2026-11-19.md`
- `R6-07_Walk-in旧入口退役观察报告.md`
- `架构旧路径收口审计报告_2026-11-23.md`（列为「已 410 退役」）

→ **e2e 脚本的注释「DEC-WALKIN-01 仍可用」与实现相反，属脚本未随裁定更新。**

### 3.2 C1 / C3：B13 的连锁反应

```python
inhouse_expected = 3   # booking1 + walk-in 甲 + walk-in 乙（三单都是当日存）
expected_charge_total = q2(nightly + walkin_total + walkin2_total)
```

`inhouse_expected = 3` 与 `expected_charge_total` 都**硬编码包含 B13 创建的第二个 walk-in**。B13 未创建 → 只剩 2 单 → C1/C3 断言必然失败。

**证据**：C1 实测输出「阻断 0 在住 **2** 待过租 **2** 笔 1376.00」——数量与金额都正好差一个 `walkin2_total`（588.00）。

→ **C1/C3 不是独立缺陷，是 B13 的派生失败。**
