## 3. DEFECT-T02-3（新发现）：审批动作码未注册

### 3.1 现象

```
动作码: privacy.retention_execute
已注册: False
→ request_approval 会抛『未知审批动作码』
```

`ApprovalActionRegistry` 中已注册的 `privacy.*` 动作仅两个：

- `privacy.export_staff`
- `privacy.pii_export_unified`

**`privacy.retention_execute` 不在其中。**

### 3.2 影响

`ApprovalService.request_approval()` 内部：

```python
spec = ApprovalActionRegistry.get(action_code)
if spec is None:
    raise ValueError(f"未知审批动作码：{action_code}。")
```

→ **无法通过正规服务层为数据清理申请审批**。运维/开发只能：
1. 直接用 `ApprovalRecord.objects.create()` 建 PENDING，再 `save()` 迁移到 APPROVED（**绕过了 action_code 注册、payload 校验、实体类型校验**）；
2. 或根本走不通，导致 DEFECT-T02-2 的审批门在实际运营中**无合法途径满足**。

### 3.3 严重性

| 维度 | 评估 |
|---|---|
| 功能性 | **中高**：审批门已实现，但无法合法产生合格审批 |
| 安全边界 | 反向影响：为了满足审批门，操作者被迫绕过注册表，削弱既有的 payload/实体校验 |
| 是否阻塞功能 | **是**（无法经正规流程执行清理） |
| 本会话复核中的绕行 | 我用 `create(PENDING)` + `save()` 模拟已批准记录——**这正是绕行示例，说明缺口真实** |

### 3.4 修复建议（供 TASK-02 责任方）

在 `apps/billing/approval_registry.py` 的注册表内新增一条 `ApprovalActionSpec`。该类的字段（据源码 `__slots__`）为：

`action_code` / `entity_type` / `title` / `request_permission` / `approve_permission` / `executor` / `payload_fields` / `expires_hours` / `api_requestable` / `validate_entity` / `sod_rule`

参考已注册的 `privacy.export_staff` 形态，建议：

```python
"privacy.retention_execute": ApprovalActionSpec(
    action_code="privacy.retention_execute",
    entity_type="RetentionExecution",          # 需与 retention.py 调用侧一致
    title="隐私数据保留期满清理执行",
    request_permission="<待定>",                # 须由负责人按 NS-E-05 逐项批准
    approve_permission="<待定>",
    executor="apps.guests.retention.plan_retention_cleanup",
    payload_fields={"policy_id": 20, "as_of": 10},   # 按实际载荷调整
    api_requestable=False,                      # 当前无 API 端点
),
```

> ⚠ **注意**：`request_permission` / `approve_permission` 属**权限码范畴**，按 NS-E-05「未逐项批准前不得新增权限码」的硬约束，**必须先由负责人逐项批准**才可填写。因此本项修复**不能只由开发方完成**，需与 OWNER-06 一并裁定。
>
> 并补一条测试：`request_approval(action_code="privacy.retention_execute", ...)` 成功返回 PENDING 记录。

**本会话不代为实现**——`approval_registry.py` 属财务审批域，且新增注册项涉及权限码（L3/L4 性质），应由 TASK-02 责任方在负责人批准权限面后执行。
