## 4. MySQL 唯一约束独立修复报告

### 4.1 交付独立性确认

| 项 | 结论 |
|---|---|
| 修复提交 | **`ef34e24`**（独立 Commit SHA） |
| 涉及文件 | `apps/guests/migrations/0009_privacy_lifecycle_governance.py`、`apps/guests/models.py` |
| 是否与 TASK-03 权限违规文件混合 | **否**（`git show --name-only ef34e24` 无 0010/0011/name_pii 任一文件）✅ |
| 与本次拦截提交的关系 | 分属两个独立提交，`ef34e24` 在前、`a580760` 在后 |

### 4.2 根因（一句话）

`RetentionPolicy` 原用**条件唯一约束**（`UniqueConstraint(condition=Q(enabled=True))`）表达「每物业每数据类别仅一条启用策略」。**MySQL 8 不支持条件唯一索引，Django 建表时该约束被静默丢弃** → 数据库层根本无唯一性；SQLite 支持 partial index 故本地全绿，MySQL（权威引擎）上重复插入成功，CI 断言落空。

### 4.3 修复方式

新增**可空唯一键** `enabled_policy_key = "property_id:data_category"`（`unique=True, null=True, editable=False`），由 `save()` 维护：启用时置值、停用时清空。该模式与同文件既有 `GuestMembership.active_guest_key` **完全一致**，未引入新机制。
