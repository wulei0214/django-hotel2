### 2.1 依实测行为修正的断言口径（非降低标准）

补齐过程中发现 4 处原假设与实际行为不符，按实测修正：

| 原假设 | 实际行为 | 处理 |
|---|---|---|
| 值班经理无 `finance_access`，应 403 | 值班经理实际持有 `finance_access` + `payment_collect` | 断言改为 201，并验证金额回显 |
| 空原因 → 400 | 服务层抛 `GuestServiceError` → 409 `BUSINESS_CONFLICT` | 断言改为 409 + 错误码 |
| 同物业可建两条 enabled 策略 | `enabled_policy_key` 唯一 | 建第二条前先停用第一条 |
| 客房组可作为无权限对照 | 该角色组在本环境不存在 | 改用夜审员 |

## 4. 缺口 3：提交拆分的如实说明

任务书 §11 建议按 6 个主题拆分，其中 TASK-04 审计修复应独立为
`fix(billing): propagate request context to collection audit`。

**实际情况**：TASK-01/02/03/04 的生产代码合并为一个提交 `cc00108`
（`feat(identity): add payment collection and membership status permissions`）。

**未补做的理由**：`cc00108` 已推送至 `origin/main`，且并行会话在其之上新增
11 个提交（含后续文档与功能批次）。改写该提交的历史会破坏协作分支稳定性，
影响其他会话的在制工作。本会话选择如实记录缺口，而非为满足形式要求重写
已发布历史。

**建议**：如需完整满足该形式要求，应由负责人决定是否在专用分支上重写历史；
或在后续独立分支补一个 `fix(billing)` 前向提交，仅记录审计修复的变更说明
（不改变实际代码归属）。
