## 1. 生产安全配置 fail-fast（已落地）

`hotel/settings.py` 的 `_validate_production_settings`（定义于 L376）覆盖四个维度：

| 维度 | 校验 | 来源行 |
|---|---|---|
| DEBUG | 生产必须为 False | L376 参数 `debug` |
| SECRET_KEY | 生产必须 **≥32 字符强随机** | L381「DJANGO_SECRET_KEY must be >=32 chars strong random」 |
| **PII_KEY** | **≥32 字符且独立于 SECRET_KEY** | L384「DJANGO_PII_KEY must be >=32 chars independent PII key」 |
| ALLOWED_HOSTS | 生产必须配置 | L376 参数 `allowed_hosts_raw` |

失败即 `raise ImproperlyConfigured("Q7 production validation failed: " + "; ".join(_prod_errors))`（L388）。

> 补充：`settings.py:26` 另有独立守卫「生产环境必须设置 DJANGO_SECRET_KEY。」，与上述 L381 的强度校验互补。

**负向测试已存在**：`apps/core/test_production_security_guard.py`
- 四维度各有负向用例（`test_debug_true_is_rejected`、`test_missing_secret_key_is_rejected` 等）；
- 另有正向基线 `test_all_valid_config_passes`（证明负向断言非假阴性）；
- 并断言**错误信息只指出变量名/原因、不回显变量值**（符合任务书「不得将密钥写入代码、测试报告或提交记录」）。

→ **该基线与任务书「生产安全配置不合规时拒绝启动」要求一致，判定 PASS。**

## 4. 「轮换脚本不在仓库」的性质判定（关键澄清）

### 4.1 事实

- `scripts/pii_key_rotation_prod.py` **不在仓库**（`Test-Path` = False；`git ls-files` 无命中）；
- 但手册**附录 C（L643-1202）附有其完整脚本全文**（约 560 行）；
- 手册 L645 明确标注：

> **状态：本手册附录完整，尚未入库。** 入库前条件：1) 在隔离环境（`DJANGO_ROTATION_SCOPE=test_hotel` + `DJANGO_DB_NAME=test_hotel`）跑通；2) 按现有做法落 `scripts/`；3) 与 `apps/guests/services.py::_pii_key_bytes` 对齐在集成验证。

### 4.2 手册第 1 节执行边界（决定性）

| 项 | 原文要点 |
|---|---|
| 执行角色 | 生产运维 / DBA 执行；安全合规复核；业务负责人批准 |
| **执行边界** | **「AI 会话与开发人员不得直接操作生产数据库、生产密钥与生产密钥轮换」**；开发阶段在隔离环境（`test_hotel`）跑通验证，失败现场提供回滚命令 |
| 前置条件 | 执行前必须开启审批单（时间/回滚预案/签字，见附录 B） |
| 凭据 | 全部凭据一次性环境变量注入；**严禁**写入代码、命令行参数、日志、聊天、IM、文档 |
| 审计合规 | 轮换脚本不新增「受控后台操作」；**不得**绕过 `reveal_phone`/`reveal_document` 业务揭示权限路径 |

### 4.3 判定

**这不是缺陷，而是已登记的安全边界。** 理由：

1. 手册**主动声明**脚本尚未入库，并给出三条明确的入库前置条件；
2. 执行边界明令 **AI 与开发人员不得操作生产密钥轮换**——本轮会话更无权将生产密钥轮换脚本入库并「跑通」；
3. 该事项在既有登记中属 `PRODUCTION_PENDING`（生产密钥托管与轮换，PROD-02）。

→ **正确处置：保持 `PRODUCTION_PENDING`，不擅自补脚本、不擅自入库、不擅自跑生产数据。**
