## 二、本轮修复的三个实证缺陷

### 2.1 改密冷却期被限流计数窗口边界截断（认证路径绕过口子）

- **现象**：同一根因两次以不同形态出现——`6b30df5` 的 SQLite 全量**偶发**红 1 例（同提交复跑即绿）；`789d313` 的 SQLite 全量**确定性**红 1 例（滑动窗口落地后与钉住弱语义的用例直接冲突）。
- **断言**：`AssertionError: 302 != 200 : 冷却期内即使口令正确也不得放行改密`——`302` 即**用户提供的正确口令穿过了冷却期**。
- **根因**：`apps/core/rate_limit.py` 的计数按**纪元对齐的固定窗口**分桶，判定（peek）只看「当前窗口起点」那一条行；冷却期没有独立的 `lock_until`，**完全由该计数行派生**（`apps/identity/services.py::check_current_password`）。于是「阈值达成后的冷却」实际只持续到当前窗口结束——落在窗口末尾时冷却几乎为零长度。
- **定级**：**合同一致性缺陷**，不是安全策略变更。合同口径写的是**固定 300 秒**，三处既有基线一致：

  | 出处 | 原文 |
  |---|---|
  | `apps/identity/services.py::check_current_password` | 「进入 `PASSWORD_REAUTH_COOLDOWN_SECONDS` 秒冷却，冷却期内即使密码正确也拒绝校验」 |
  | 《前端opt-in与三开发线复核修复报告_2026-11-26.md》 | 「5 次失败后进入 300 秒不可重试窗口」 |
  | 《文档处置清单_重复过期冲突_2026-11-27.md》 | 「5 次失败后进入 300 秒冷却」 |

  固定窗口把冷却截断到 0~300 秒，**短于合同约定的 300 秒**——是实现未兑现既有约定，不是新增或变更策略。
- **修复**：`ce549b7`（计数改滑动窗口：计数行在最后一次计数后再存活 window_seconds，跨窗口边界不清零）+ `15cec54`（把与之冲突的既有断言改为合同口径）。
- **先红后绿**（实测）：换回整改前实现 → **3 项红**，均 `302 != 200`；换回整改后实现 → **32 例全绿**（skipped=1）。
- **修复前证据归档**：`evidence/g14-20261127-cooldown-defect/`（含 README 与两份失败日志）。

### 2.2 `identity.0016_legacy_staff_mapping` 在 MySQL 上不可逆

- **现象**：MySQL 全量在测试库销毁阶段报 2 个 error（SQLite 无此问题）。
- **根因**：0016 把 `Meta.indexes` / `Meta.constraints` 拆成了独立的 `AddIndex` / `AddConstraint` 操作（手写迁移偏离 Django 标准形态），反向迁移时 `DROP INDEX` 撞上外键依赖。0015 里已有同样的注释与正确写法，0016 漏了。
- **修复**：`789d313`——索引与唯一约束改为随建表内联。开发库 0014/0015/0016 尚未应用，改迁移文件无部署风险。修复后 MySQL 上 `apps.identity.test_arch04_retirement` **40 例全过**。

### 2.3 ARCH-02 / ARCH-03 处置矩阵的汇总计数错误

- **现象**：矩阵 §四「处置汇总」与 §三「逐行表」对不上——`REDIRECT` 汇总写 13（5 已有 + 8 建议）但括注实列 10 条路径、逐行表标 REDIRECT 的共 15 行；`410` 段写「7 条写入口」但逐行表 `insert*`/`delete*`/`update*` 共 19 行（且本就含于 31 条已退役之内，原口径重复计数）。
- **另一处发现**：`bfc2fb4` 之后的退役**代码实施**（`950eec8` 路由 302、`56c050a` 模板退役 8 个）早已入库，矩阵绑定 SHA `0ca1ce4` **早于**这两个提交，描述的是实施前状态——矩阵不是「待实施清单」而是「实施前快照」。
- **修复**：`1c11d54`（经 `da0894b` 合入）——按逐行表 + 代码复核订正汇总计数，原始口径留痕不静默改数；两份矩阵增列「实施终态（2026-11-27 复核）」与「计数订正说明」；31 条「已退役」逐条代码复核确认属实（唯一例外 `folio/` 仍恒返回 404）。
- **同步补强**（5 条此前无覆盖的契约断言）：退役只读入口**不得产生任何写库**（业务表 + 审计表，`CaptureQueriesContext` 拦截 SQL + 14 张表行数快照）；现存模板不得再指向已退役旧入口；`RedirectView` + `functools.wraps` 形态导致的门禁覆盖盲区单独立项并加清单漂移守卫。

### 4.6 住客中心浏览器验收未能走通的原因（**非产品缺陷**）

即：**通用管理中心的 pms-ux 接线正常**，失败原因是验收脚本的权限授权范围固定在房态中心。正式验收口径仍以房态与库存中心 28/28 为准（任务书要求的「房态操作表单未保存提醒 / 草稿 / 失焦校验」亦在该中心）。
