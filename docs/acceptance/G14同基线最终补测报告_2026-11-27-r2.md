### 2.2 R7 —— 取证隔离库改名 `test_hotel` → `test_hotel_e2e`

| 项 | 内容 |
|---|---|
| 根因 | Django 的 MySQL **测试库名 = `test_` + `DJANGO_DB_NAME`**；开发库名是 `hotel`，故 Django 的测试库就叫 `test_hotel`。取证隔离库此前也取名 `test_hotel` → **任何一次 `manage.py test` 的收尾阶段都会把它删掉**（2026-11-27 实测发生过一次，丢失已建好的隔离库） |
| 本机授权现状（实测） | 应用账号 `hotelhotel@127.0.0.1` 仅对 `hotel`（开发库，禁用作取证库）与 `test_hotel`（Django 测试库）有授权，且 `USAGE ON *.*` 无建库权限 → **第三个隔离库必须由 DBA 侧一次 GRANT** |
| 已落地 | 默认隔离库名改 `test_hotel_e2e`；`prepare_isolated_db.py` 无授权时打印可执行 GRANT 原文并以退出码 2 退出（不抛裸异常）；`e2e_full_chain.py` 增加撞名告警；新增四个正式取证工具（隔离库准备 / 取证服务 / E2E 取证器 / 九岗位取证器）；新增《取证隔离库改名与DBA授权_2026-11-27》 |
| **未落地** | **DBA 授权尚未在本机实例生效**：两次执行均未落到本项目使用的实例（`information_schema.SCHEMATA` 实测无 `test_hotel_e2e`）。因此本轮 E2E 与九岗位矩阵仍跑在旧名 `test_hotel` 上——**工具链默认名已切到新名，但库本身待授权后一次性迁移** |
| 撞名告警口径 | 告警而非拒绝。撞名影响的是隔离库的**复用**，不是**本次取证的正确性**；早期做成硬拒绝会在授权落地前把 E2E 能力整体堵死（那时本机没有任何可用隔离库名），属能力回退。告警块同时打印 GRANT 原文 |
