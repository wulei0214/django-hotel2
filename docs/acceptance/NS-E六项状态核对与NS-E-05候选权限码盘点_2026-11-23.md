### 2.1 现状基线（现取，不凭记忆）

| 模块 | 数量 | 权限码 |
|---|---:|---|

| hotelapp | 9 | `business_date_reopen` / `export_approve` / `export_pii` / `finance_access` / `guest_document_reveal` / `guest_phone_reveal` / `night_audit_execute` / `no_show_handle` / `room_release_ready` |

### 2.2 候选权限码 A —— FIN-06：收款录入专项码

| 字段 | 内容 |
|---|---|
| **候选权限码** | `billing.payment_collect` |
| **业务动作** | 在前台/财务页录入一笔收款（`POST /api/v1/billing/payments`），使 Folio 产生 `Payment` 事实并可能推进预订状态 |
| **适用岗位（九岗位）** | 主要：**前台**（收现/刷卡登记）、**财务**（补录）；不应授：客房服务员、餐饮服务员/主管、停车安保 |
| **数据范围** | 仅本物业（`property_obj`）内、本人可访问的 Folio；跨物业一律拒绝 |
| **操作类型** | **创建**（产生财务事实） |
| **审批要求** | **否**（收款是日常操作）；但 **退款** 已由 `billing.refund_request/approve/execute` 三方分离约束，收款不与之合并 |
| **审计要求** | 必须写 `AuditEvent`：操作者、物业、Folio、金额、币种、支付方式、营业日、reason（若为改单/补录需 ≥8 字符） |
| **拒绝场景** | ①无 `billing.payment_collect` 时调用端点 → 403；②跨物业 Folio → 404/403；③营业日 CLOSED 且无渠道豁免 → 409；④金额/币种非法 → 400 |
| **测试用例** | ①前台持有 → 200 且产生 Payment+审计；②无该码岗位（如客房服务员）→ 403；③跨物业 → 拒绝；④关账后 → 409；⑤重复提交同 Idempotency-Key → 返回首次响应 |

**现状**：`apps/api/billing_center.py:668` 仅用 `_require_finance_access(request)`（即 `hotelapp.finance_access`），**无收款专项码**。
**风险**：任何持 `finance_access` 者均可收款，与「最小权限」不符；且 `finance_access` 同时覆盖查看/导出等多动作，粒度粗。

### 2.3 候选权限码 B —— MB-11：会员状态变更专项码

| 字段 | 内容 |
|---|---|
| **候选权限码** | `membership.status_manage` |
| **业务动作** | 暂停/恢复会员（`POST /api/v1/staff-center/memberships/{id}/action`，`action=suspend\|restore`），改变 `GuestMembership.status` |
| **适用岗位（九岗位）** | 主要：**前台**（日常）、**值班经理**（恢复/争议处置）、**店长**（兜底）；不应授：客房服务员、餐饮服务员/主管、停车安保、夜审员 |
| **数据范围** | 仅本物业内会员；`Guest` 归属校验必须同物业 |
| **操作类型** | **修改**（状态变更） |
| **审批要求** | **否**（单步状态变更）；但**恢复**若涉及权益补发，需另行评估是否要求第二人 |
| **审计要求** | 必须写 `AuditEvent`：操作者、物业、member_no、from_status→to_status、reason（1–240 字符，现实现已强制） |
| **拒绝场景** | ①无该码 → 403；②非法状态跳转（如 TERMINATED→ACTIVE 需走 restore 语义）→ 409；③跨物业 → 拒绝；④reason 缺失/超长 → 400 |
| **测试用例** | ①授权岗位 suspend 成功并留审计；②未授权岗位 → 403；③重复 suspend 幂等（`changed=false`）；④跨物业 → 拒绝；⑤`restore` 时目标已被他人恢复 → 冲突提示 |

**现状**：`apps/api/staff_center.py:412-419` 使用 `hotelapp.change_vip`，且**代码 docstring 自述**「`membership.suspend` 专项权限码尚未在字典中登记」。
**风险**：会员状态变更与「查看/编辑会员资料」共用同一权限，无法单独撤销高风险动作。

### 2.4 盘点附带观察（不改码，仅登记）

| 观察 | 事实 | 影响 |
|---|---|---|
| O-1 | `hotelapp.finance_access` 承担收款/查看/导出等多动作 | 粒度粗，是 FIN-06 的直接成因 |
| O-2 | `hotelapp.change_vip` 承担会员查看/编辑/状态变更 | 粒度粗，是 MB-11 的直接成因 |
| O-3 | 权限码命名空间混用：`hotelapp.*`（9 个）与领域名（`billing.*`/`inventory.*`）并存 | 新增码的命名前缀需负责人明确（建议：纯领域前缀，不再新增 `hotelapp.*`） |
