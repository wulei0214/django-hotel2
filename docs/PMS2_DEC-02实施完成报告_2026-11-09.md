## 3. 关键设计决策（与 DEC-02 基线逐条对应）

| 基线条款 | 实现方式 |
|---|---|
| §2.1.1 原始负债冻结 | `amount` 不可变（save 校验+不可变查询集）；调整独立记录 |
| §2.1.2 remaining 不得普通编辑回增 | 模型 save 校验回增必须 `sanctioned_increase=True`（仅 `execute_adjustment` 传入）；普通路径仍拒绝 |
| §2.1.3 独立可追溯调整凭证 | `BillingAdjustment` + `LedgerEntry(ADJUSTMENT)` 关联 |
| §2.1.5 抵扣/冲销不伪装退款 | 抵扣凭证为 `ADJUSTMENT` 类型（非 REFUND）；不生成 REFUND 凭证 |
| §2.1.6 财务发起+值班经理批准 | SoD：`request_adjustment(requested_by=finance)` → `approve_adjustment(approved_by=duty)`；自批拒绝 |
| §2.1.7 净额可重建 | `liability_net_snapshot`：原始 − 抵扣 + 增加 − 已退款 = 净额 |
| §2.2 并发不重复占用 | 抵扣执行与退款共用负债行锁（`select_for_update`）串行化 |
| §2.2 未审批不影响净额 | 净额仅统计 EXECUTED 状态调整 |
| §3.1.5 异常放行不建正式负债 | `consume_approved_exception_release` 仅置 RELEASED，不调 `register_refund_liability` |
| §3.1.7 受控转负债 | `settle_exception_release(outcome=CONVERT_LIABILITY)` 走 `register_refund_liability` 全量重验 |
| §3.1.8 无需退款按审批关闭 | `outcome=CLOSE_NO_REFUND` + `verify_note` 必填 |
| §3.2 申请人≠审批人 | `approve/reject` 均校验 `requested_by_id == approved_by.pk` 拒绝 |
| §3.2 跨物业隔离 | 所有服务按 `property_obj` 过滤；跨物业操作返回"不存在" |
