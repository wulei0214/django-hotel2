### 删除原则

本轮不直接删除任何审计证据、实施记录或正式决策。经核对，当前多数“重复”文件职责并不相同（决策、需求、实施、测试证据），直接删除会损害追溯性。确认被 V2.3 替代的旧 PMS3 文件只降级归档，不删除。真正无效的临时草稿、重复导出件或无任何引用的文件，需逐个核验 Git 历史、内部链接和证据用途后再删除。

## 9. 文件命名规则（2026-11-10 起强制）

1. 新建或实质性修订的 Markdown 文件统一使用：`主题_YYYY-MM-DD.md`。
2. 版本号放在主题中，日期后缀放在最后，例如：`PMS3.0全项目开发最终方案V2.3_2026-11-10.md`。
3. 历史审计文件的原始执行日期不得伪造；归档副本如需改名，文件正文必须保留原始 SHA、执行日期和证据日期。
4. 当前不批量重命名全部 76 篇旧文件：现有文档之间存在大量相对路径引用、验收证据索引和历史记录路径。未完成全仓链接扫描与引用替换前批量改名会造成文档断链。本轮先建立唯一分类索引和命名规则；下一轮需执行“全仓链接扫描→批量改名→全量引用更新→链接检查”后，才能完成旧文件统一改名。
5. 非 Markdown 的 JSON、SQL、日志、备份和证据文件按原始格式及证据编号管理，不强行追加日期破坏脚本引用。
