# 敏感字段权限边界设计（RBAC 决策 7-2 · 待店长确认稿）

> 评审点："员工月薪、身份证号、会员联系方式、车牌号哪些岗位必须看到完整值？哪些必须遮罩？"
> 你的初步意向：**月薪 = 员工本人/财务/店长可见**，其余字段全员可见；
> 你要求提供参考与详细边界设计后再拍板。本文给出行业参考、建议方案与实施成本，供决策。

## 一、行业参考（评审稿 §9 三家产品的公开设计）

| 产品 | 敏感字段处理 |
|------|--------------|
| Cloudbeds PMS | 薪资类仅 Owner/Manager 角色可见；住客身份证对 Housekeeper 完全不可见（不是遮罩，是字段级隔离）；报表导出单独权限 |
| Mews Operations | "Sensitive reports" 与 "Customer data" 是独立权限；非管理员不能自我提权；Full card/ID view 需显式授予 |
| Oracle OPERA Cloud | 字段级 Data Masking（如证件号默认 `****`，点"显示"需 AR 扩展权限并写审计）；员工薪酬仅 HR/GM 角色可见 |

**共同规律**：① 薪酬是最敏感字段（连目录可见性都收紧）；② 证件号默认遮罩 + 点击查看留审计；
③ 清洁/餐饮一线岗位对住客证件零需要；④ 导出比查看更严。

## 二、逐字段边界建议（结合本项目岗位与你的意向）

### 1. 员工月薪（Staff.月薪）—— 建议采纳你的意向 ✅

| 角色 | 列表页 | 详情/行内编辑 | CSV 导出 |
|------|--------|---------------|----------|
| 员工本人 | ✅ 仅自己的 | ✅ 仅自己的 | ❌ |
| 财务 | ✅ | ✅ | ✅（export_pii） |
| 店长 | ✅ | ✅ | ✅（export_pii） |
| 值班经理 | ❌ 列遮罩 `****` | ❌ | ❌ |
| 前台/客房服务员等 | ❌ 列遮罩 | ❌ | ❌ |

- 实现要点：员工管理列表对无 `staff.compensation.view` 权限者渲染 `****`（列也隐藏）；
  行内编辑的月薪输入框同样置灰。财务的 `view_staff` 已在迁移 0014 授予（只读目录）。
- 成本：**低**（一个模板过滤器 + 一个权限点）。建议本版本即做。

### 2. 顾客身份证号（Client.身份证号）—— 建议比你意向略收紧

你的意向：全员可见。行业惯例是"前台/财务/店长完整可见，其他岗位遮罩"。
考虑到本系统**前台本来就需要核验证件**，建议：

| 角色 | 列表 | 详情 | 导出 |
|------|------|------|------|
| 前台/值班经理/财务/店长 | ✅ 完整 | ✅ 完整 | ✅（export_pii） |
| 客房服务员 | 遮罩 `1101**********0011`（可见前4后4） | 同左 | ❌ |
| 餐饮/停车岗位（预留） | 遮罩 | 遮罩 | ❌ |

- 依据：客房服务员工作面只有房号与清洁状态，不需要证件号（Cloudbeds 对 Housekeeper 直接隔离）。
- 成本：**低**（员工页面只有一个Staff列表；顾客列表按权限遮罩一个列）。

### 3. 会员联系方式（Vip.联系方式）—— 建议与你意向一致，全员完整可见 ✅

- 会员营销/回访是全员都可能执行的动作，本项目无会员模块外的一线岗位划分；
- 唯一收紧点：**CSV 导出**仍需 `export_pii`（已实现 ✅）。

### 4. 车牌号（Park.车辆牌号）—— 随模块隐藏，暂无需设计 ✅

- 停车模块已对接第三方（决策 7），字段随模块隐藏；第三方对接时由第三方负责，
  届时仅"停车安保"角色需要完整车牌（对应权限点 `parking.plate.view`，方案 §4.2 已预留）。

### 5. 补充建议：财务流水的"经手人"与账单明细

- `finance_access`（值班经理可见）按方案 §4.2 属"汇总可见、不下钻支付明细"——
  当前实现是整页可见，单店阶段可接受；多店启用时拆 `finance.summary.view` /
  `finance.details.view` 两级。**暂不动。**
