## 2. 新增数据模型

- `Reservation`：预订主单，状态 `PENDING / CONFIRMED / CANCELLED / EXPIRED / CHECKED_IN / CHECKED_OUT / NO_SHOW`
- `RoomTypeInventory`：房型 × 营业日库存，`sold` 为已确认占用，`held` 为待支付占用
- `Payment`：支付流水，`provider_ref` 唯一，支撑回调幂等
- `LedgerEntry`：统一账本，金额带符号；`reference` 唯一，支撑幂等入账
- `AuditLog`：结构化审计，记录 before/after、操作人、IP

旧表 `FinanceRecord`、`Folio` 保留为历史只读；`0011` 已把旧数据复制到 `LedgerEntry`。

### 房费入账口径

房费统一按「住宿日」入账，`reference = stay:<住宿单id>:<住宿日>`：

- 夜审为当晚在住订单过租一晚；
- 退房时自动补齐住宿期间尚未过租的夜晚；
- 入住、续住、散客直入只登记住宿区间和押金，不重复写房费。

因此重复夜审、夜审后再退房都不会重复收房费。

## 4. API v1

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/availability` | 查房：`room_type`、`check_in`、`check_out` |
| POST | `/api/v1/reservations` | 下单并 hold 库存，支持 `Idempotency-Key` |
| GET | `/api/v1/reservations/<booking_no>` | 查询预订与支付流水 |
| POST | `/api/v1/payments/callback` | 支付回调，HMAC-SHA256 验签 |
| GET | `/api/v1/openapi.json` | 最小 OpenAPI 描述 |

### 4.1 查房

```bash
curl "http://127.0.0.1:8000/api/v1/availability?room_type=大床房&check_in=2026-11-01&check_out=2026-11-03"
```

### 4.2 下单

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/reservations" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: demo-001" \
  -d '{"name":"张三","phone":"13800000000","room_type":"大床房","check_in":"2026-11-01","check_out":"2026-11-03","rooms":1}'
```

返回 `booking_no`、`status=PENDING`、`total_amount`、`expires_at`（默认 hold 15 分钟）。

### 4.3 支付回调

请求体按原始字节计算 HMAC：

```text
signature = hex(hmac_sha256(PAYMENT_WEBHOOK_SECRET, raw_body))
```

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/payments/callback" \
  -H "Content-Type: application/json" \
  -H "X-Signature: <hex signature>" \
  -d '{"booking_no":"R20261101ABC123","provider_ref":"PAY-001","amount":"600.00","provider":"mock","status":"SUCCESS"}'
```

回调成功后将 hold 转为 sold、预订置为 `CONFIRMED`，并写 `LedgerEntry(PAYMENT)`；重复回调返回 `duplicate=true`，不会重复入账。
