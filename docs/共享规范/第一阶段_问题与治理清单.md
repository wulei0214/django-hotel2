> 分类规则（V1.1 任务 10）：**已证实问题** = 有直接代码/配置证据与复现方法；**待核实风险** = 存在疑点但本次未完成核实闭环；**治理建议** = 无即时风险的改进项。

### P-01｜ARCHITECTURE.md §2 API 规范与代码事实不符（DRF/serializers/统一响应/EXCEPTION_HANDLER 均未落地）
- **风险等级**：高
- **文件路径**：`ARCHITECTURE.md` §2；对照 `apps/api/views.py`、`apps/api/urls.py`、`hotel/settings.py`
- **证据**：① `apps/api/serializers.py` 不存在；② `grep -rln "rest_framework" apps/ hotel/ --include="*.py"`（排除 migrations）= 0 命中；③ `apps/api/responses.py` 不存在；④ settings 无 `EXCEPTION_HANDLER` 配置；⑤ 实际 API 为普通 Django 函数视图 + `api_guard` 装饰器 + `_body/_date/_integer` 手工解析；实际响应为各端点自定义 JSON（如 availability 顶层为 property/check_in/rooms/data）
- **根因**：ARCHITECTURE.md 由治理早期草稿生成，把"目标态"写成"现状"；此后 V1.1 §6 第二阶段任务 1 尚未执行修订
- **影响范围**：所有 AI 与新人按 ARCHITECTURE.md 字面开发会创建第二套 DRF 实现/响应格式（正是 V1.1 §1.3 要防止的分裂）；契约评审失真
- **参考文档**：V1.1 §3.1/§3.5；docs/PMS2.0_当前版本/02_技术架构与数据模型/PMS2技术功能说明文档_2026-11-12.md
- **复现/核验方法**：`grep -rln rest_framework apps/ --include="*.py" | grep -v migrations`；`ls apps/api/serializers.py apps/api/responses.py`；`grep -n EXCEPTION_HANDLER hotel/settings.py`
- **修复建议**：第二阶段任务 1 修订 ARCHITECTURE.md——将 DRF/Selector/统一响应明确改写为"目标态 + 迁移计划"，现状描述改为"函数视图 + api_guard + 领域异常"并登记为现行事实规范；修订需项目负责人批准（L3）

- **风险等级**：中
