## 3. 口径自声明 metadata（§8.8）

每报表响应 `data.metadata` 含：`property` / `period`（含 `date_basis`、`start`、`end`、`days`）/ `status_scope` / `currency` / `source_system = "PMS2"` / `generated_at`。已测试（`test_metadata_present_on_all_reports`、`test_default_range_is_last_seven_days`）。

- `occupancy`：`date_basis = 住宿日（stay_date，逐日库存快照）`
- `adr`：`date_basis = 营业日（LedgerEntry.business_date）`
- `revenue`：`date_basis = 营业日（LedgerEntry.business_date）`
- `housekeeping`：`date_basis = 自然日（AuditEvent.created_at，非营业日）` —— 显式标注，符合 §8.7
- 多币种：`adr` / `revenue` 主序列仅结算币种，其他币种单列 `other_currencies` **不相加**（符合 §8.6），已在 `metadata.status_scope` 中声明「仅对物业结算币种计算；其他币种房费单列不相加」

## 4. 关键发现与待确认项（阻止会计报表验收）

### 4.1 DEC-16 未签署（硬门禁）

- 硬冻结清单 §9（line 152）：`- □ DEC-16 已签署` 未勾选。
- 2026-11-12 校准（line 211）：原 DEC-16 的**免费房、内部房、停用房、税费、佣金及多币种细则**「仍按各自正式决策记录处理，不得误标为已确认」。
- §10.10（建议执行口径）确认了方向（OCC / ADR / RevPAR / 实收分开 / 多币种不相加），但同节「仍需补齐的参数」（line 193）明确「停用房分母处理、免费房 / 内部房间夜口径、税费排除口径、渠道佣金口径、多币种折算汇率和时点」**仍需补齐**。
- **项目规则**：DEC-16 未签署前，不得把现有汇总卡片作为会计报表验收。

### 4.2 未实现的口径端点

- **RevPAR（§8.3）**：当前仅实现 ADR，无 RevPAR 端点；报告中心 UI / OpenAPI / 测试均无 RevPAR。
- **实收（§8.5）**：`revenue` 报告以 LedgerEntry 为准（正确，满足 §8.4），但「实收 = 成功 Payment − 成功 Refund」未作为独立端点暴露。首页看板 `dashboard_finance` 有 `settled = Payment SUCCEEDED`，但属首页概览且未与收入区分标签。

### 4.3 已确认方向但代码未特殊化、目前保守实现的项（即「待确认细则」）

代码当前对以下项**不做任何特殊换算**，直接采用 `RoomTypeInventory.sold` 与 `LedgerEntry ROOM_CHARGE`：

- **免费房 / 内部房**：DEC-16 §8.6 要求「单独定义」；§8 待确认（line 135）要求明确如何计入已售间夜。当前免费房 / 内部房被计入 `sold`（无区分）。→ 待负责人明确后补。
- **停用房分母**：代码已剔除 `out_of_service`（与 §10.10「可售 = 总 − 停用」一致）；但 §8（line 135）仍列「停用房是否从分母剔除」为待确认，且 DEC-16 正式复选框未勾选 → 属「方向已确认、签名待补」。
- **税费（§8 line 135）、渠道佣金（§8 line 135 / §10 line 193）**：代码未排除 / 未计入，因无依据不得自行补值（符合冻结纪律，但意味着报表净收入不含这些处理）。
- **多币种折算（§10 line 193）**：当前仅分组展示、不相加，但无汇率折算与时点 → 多币种汇总规则待确认。

### 4.4 正面确认（代码未越界）

代码**没有**为上述未决参数编造数值或规则（未写死免费房比例、未自行扣税费、未自行折算汇率），保持只读聚合与方向性口径一致。这是符合治理纪律的正确行为——缺失口径以「不实现 / 不伪造」方式冻结，而非以猜测落地。
