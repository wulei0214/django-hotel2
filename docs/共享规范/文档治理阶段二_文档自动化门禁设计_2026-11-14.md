# PMS 文档自动化门禁设计（文档治理阶段二）
> 文档编号：GOV-014 ｜ 类型：GOVERNANCE ｜ 状态：REFERENCE ｜ 版本域：跨版本 ｜ 业务模块：文档治理

> 性质：阶段二设计交付；阶段三批次 5 落地。目标：方案 §10 的五类检查进 CI，杜绝"台账/索引数天内腐化"再次发生（阶段一 R10），同时不破坏既有 Django/Ruff/Black/mypy/双引擎测试/OpenAPI 守卫。

## 1. 检查项设计

| # | 检查 | 规则要点 | 拦截策略 |
|---|---|---|---|
| C1 | 链接检查 | 全口径：markdown 链接 + `docs/` 显式提及 + **省略前缀相对引用**（`共享规范/xxx`、`00_项目基线与决策/xxx` 等按 docs/ 补全尝试）+ 根目录三入口 + 目录引用按存在性；锚点检查 v2 再做 | 渐进：存量断链冻结进基线文件，只拦**新增**断链（沿用 mypy-baseline 模式） |
| C2 | 状态元数据检查 | 新增/修改的正式文档头部必须含编号元数据块（设计方案 §5）；SUPERSEDED 必须有指向；DRAFT 不得被索引引用 | 只对**新增文件**强制；存量豁免 |
| C3 | "当前值"单源检查 | 除《当前状态总览》与历史快照（带日期后缀或 ARCHIVED 标记）外，正式文档正文出现"当前 main HEAD/当前 OpenAPI/当前 X 项测试"类断言即告警 | warn 起步，阶段四转 error |
| C4 | 重复检测 | blob 哈希分组；白名单：27 个空 `__init__.py`、两份 openapi.json 受控镜像；docs/ 内出现新的完全相同文件即拦 | error |
| C5 | 基线 SHA 核验 | 40 位十六进制且前后非十六进制字符（排除 SHA256 校验和误报——阶段一 a79b205d 教训）；`git cat-file --batch-check` 验证存在性 | error（引用不存在的提交） |
| C6 | 证据保护 | docs/acceptance/ 与 06/evidence/ 下既有文件出现修改/删除/改名即拦 | error |
| C7 | 追加节检测 | 活文档（状态总览/矩阵/路线/索引）出现同一 H2 标题重复出现≥2 次（追加式续写特征）即 warn | warn |

## 2. 工具实现

- 新增 `scripts/docs_link_check.py`（正式工具，非临时脚本）：
  - 子命令：`check`（全量检查，供 CI 与本地）、`baseline`（生成/更新冻结基线 JSON）、`report`（人读输出）。
  - 输入：git 跟踪清单 + 逐文件内容扫描（复用阶段一只读管道逻辑：`git show` 逐文件，规避本机 `git grep` GBK 乱码问题——已验证的坑，工具内固化）。
  - 输出：`docs/共享规范/docs_gate_baseline.json`（冻结基线，diff 模式判新增违规）。
  - 依赖：仅标准库 + Git；运行预算 <2 分钟（基线树 730+ 文件实测量级）。
- 中文路径全程 UTF-8；对 Windows 大小写不敏感做显式大小写比对（R5 修复后断言唯一大小写）。

## 3. CI 集成

- django-ci.yml 新增 `docs-lint` job（Python 3.9，与现有一致）：`python scripts/docs_link_check.py check --baseline docs/共享规范/docs_gate_baseline.json`。
- 与既有 job 并行，不改变 Django/mypy/MySQL/OpenAPI 守卫逻辑。
- 触发路径过滤：`docs/**`、`readme*.md`、`ARCHITECTURE.md`、`AGENTS.md`、`scripts/docs_link_check.py`、基线文件。
- 本地等效命令写入 AGENTS.md 交付前检查节（一行）。

## 4. 渐进治理与豁免

- 首轮基线文件登记阶段一已识别的全部存量断链（13 STALE + ~40 残留——批次 1 修复后基线应趋近只含占位符白名单）。
- 占位符白名单：`<date>`、`<N>`、`<YYYYMMDD>`、`*.md`/`*.log` 通配、`docs/...` 省略写法。
- 豁免文件：docs/acceptance/ 历史日志（只验证存在性不做链接扫描）、phase0 正文。
- 基线文件更新必须与修复同提交（"修一条删一条"），防止基线变成掩蔽所。
