## 七、第四主线：全链路与资金流转最终验收

### 7.1 统一业务验收场景

押金比例 **30%** ｜ 测试订单金额 **¥688.00** ｜ 应收押金 **¥206.40**

1. 可售查询 → 创建订单。
2. 支付意图 → 回调确认。
3. 排房 → 入住。
4. 服务端计算押金 → 账单记账。
5. 夜审 → 房费过账。
6. 退房 → 房态 VACANT + 清洁 DIRTY。
7. 退款申请 → 申请人同人审批返回 403。
8. 店长审批 → 财务独立执行成功。
9. 五张报表核对 → 完成业务追溯。

### 7.2 链路硬性要求

- 全流程使用**同一笔订单和同一个 Guest**。
- 所有资金记录可追溯到原始交易；押金不错误计入营业收入。
- 退款不能重复执行；同人审批不得绕过职责分离（SoD）。
- 退房后房态不能直接变成 CLEAN。
- 报表必须反映真实账本和业务状态。

### 7.3 五张固定报表

1. 入住率（occupancy）。
2. ADR 平均房价（adr）。
3. 营业收入（revenue）。
4. 客源分析（guests）。
5. 清洁效率（housekeeping）。

> 验收时必须核对退款、押金和房费的**会计口径**，不能只检查报表页面能否显示数字。按《报表口径核验与 DEC-16 验收门禁》，DEC-16 未签署前仅作运营/监控看板，不得按会计报表验收。链路纳入 G14-07 / G14-09，九角色参与其中的权限动作。
