## 3. OpenAPI 双快照事实（DOC-13 现状核验）

- 权威快照：`docs/PMS2.0_当前版本/03_API接口与前后端规范/接口文档/openapi.json`；兼容镜像：`docs/接口文档/openapi.json`。两者在 f13e32f **逐字节一致**（SHA256 前 16 位 `3ae56c847372a7e2`，923585 字节）。
- 实际规模：**116 paths / 118 operations**；操作级状态键为 `x-contract-status`，实测 **verified 93 / partial 25**（核查轮次逐项解析统计；readme"个别 partial"表述失实，索引"113/115、90 verified"为 f13e32f 接线前的过期值）。
- 守卫链：`apps/api/test_openapi_schema.py` 以 `read_bytes()` 逐字节断言两快照一致（OPENAPI_MIRROR_SNAPSHOT 路径硬编码）；`openapi-snapshot.yml` 在 schema 变更时自动导出并同步两份文件。
- 结论：双快照体系当前健康；任何路径调整必须同步改测试常量与 workflow，禁止出现第三份快照。

## 6. 盘点方法与可复现命令

全部结论可由下列只读命令复现（Git Bash）：

1. 文件清单与规模：`git -c core.quotepath=false ls-tree -r -l f13e32f -- docs/`
2. 内容重复分组：`git ls-tree -r -l` 输出按 blob SHA 分组（4 组，见重复清单）
3. 路径引用扫描：对 116 个 md 逐个 `git show f13e32f:<md> | grep -oP 'docs/[^\s"\x60(),;，。；、）]+'`，汇总得 434 个（来源,提及路径）对、355 个唯一目标
4. 断链分类：提及目标与 `ls-tree` 跟踪清单/目录前缀集/文件基名集三类比对（STALE/DEAD/NARR/DIRREF）
5. SHA 核验：`git grep -ohE "[0-9a-f]{40}"` 提取后经 `git cat-file --batch-check` 全部可解析（唯一疑似 `a79b205d…` 实为 openapi.json 的 SHA256 文件校验和，非提交号）
6. OpenAPI 计数：python 解析权威快照 paths/operations/x-contract-status
7. 测试证据：`grep "^Ran"` 核对 evidence 日志

扫描口径限制（如实登记）：①仅扫描 `docs/` 前缀的显式路径提及，`共享规范/xxx` 等省略前缀的相对引用未纳入，零引用名单偏保守（实际零引用 ≤ 24）；②根目录 readme/ARCHITECTURE/AGENTS 的被引用情况未纳入机械扫描；③目录引用仅判定"目录是否存在"，未检查锚点。上述口径统一纳入阶段五门禁设计。
