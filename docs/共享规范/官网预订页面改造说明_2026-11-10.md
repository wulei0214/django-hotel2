# 顾客预约官网页面改造说明

- 状态：已实施第一版页面改造，待本地联调与产品验收
- 日期：2026-11-04
- 适用入口：`/reserve/`
- 实现文件：`templates/public/booking.html`

## 1. 改造目标

将原有偏工具型的在线预订表单，升级为适合中国单体酒店运营的中文酒店官网式预订体验。视觉方向采用“高端酒店品牌感 + 精品酒店简洁体验”，借鉴酒店官网的信息层级、沉浸式首屏和清晰预订入口，不复制希尔顿商标、文案或专有素材。

## 2. 页面信息架构

1. 顶部品牌导航：首页、酒店介绍、酒店设施、客房预订。
2. 首屏品牌区：酒店名称、品牌文案、主视觉和预订引导。
3. 快速预订栏：入住日期、离店日期、房间数量、成人数量。
4. 酒店介绍：酒店氛围与服务介绍。
5. 设施展示：当前为通用展示文案，不代表系统已核实酒店实际设施。
6. 客房与预订：显示 API 返回的房型、逐晚价格、可售数量。
7. 入住人资料：姓名、联系电话。
8. 预订结果：预订编号、状态、价格与可用的本地模拟支付/取消操作。
9. 页脚：酒店名称及预订服务说明。

## 3. PMS 业务边界

本次只调整顾客端模板结构、样式和文案，不调整 PMS2 模型、业务服务、库存规则、价格计算、预订状态机、支付账务或 API 路由。

页面继续调用既有接口：
- `GET /api/v1/availability`
- `POST /api/v1/reservations`
- `GET /api/v1/reservations/{booking_no}`（请求头 `X-Booking-Token`；不得使用手机号 query，本页当前未增加订单查询表单）
- `POST /api/v1/reservations/{booking_no}/cancel`
- `POST /api/v1/payments/intents`
- `POST /api/v1/payments/callback`（仅开发/测试环境模拟回调）

原有前端脚本整体保留，继续使用 CSRF、Idempotency-Key、服务端库存查询及服务端价格快照。模拟支付按钮仍受服务端模板变量 `mock_payments_enabled` 控制，不将其包装成真实支付。

## 4. 已知限制与上线前待办

- 当前主视觉与介绍配图使用外部 Unsplash 图片地址作为临时演示素材。上线前应替换为酒店自有、已获授权的真实照片，并建议纳入项目静态资源或受控 CDN，避免第三方图片不可用。
- 当前酒店介绍、设施展示是通用占位文案；产品/酒店运营人员需确认真实地址、设施、服务、入住/退房时间、联系电话、政策后再发布。不得把占位设施描述当作已核实事实。
- 目前房型卡片展示 API 实际返回的房型名称、可售数量、逐晚价格；尚无酒店真实房型图片、面积、床型、设施字段的稳定数据契约，因此没有虚构这些信息。
- 顾客订单查询 API 当前存在并使用 Booking Access Token 请求头；本页面没有新增订单查询表单。订单访问凭据不得放入 URL query、浏览器历史或 Referer。
- 未新增儿童人数输入，因为现有页面创建预订 payload 固定传 `children: 0`；在 API 与容量规则评估前不在 UI 暴露一个无法生效的选项。
- 本次没有接入微信支付、短信、邮件、会员登录或多酒店搜索。
- 需要在真实酒店数据环境验证：日期边界、无房、库存不足、多房间、重复提交、预订过期、取消释放库存、开发环境模拟支付、生产环境模拟支付隐藏与服务端拒绝。
- 当前仅完成代码托管层面的模板改造，未运行 Django 测试、浏览器 E2E、响应式截图或真实支付测试。

## 5. 验收清单

- [ ] 桌面端 1440px、平板端 768px、手机端 390px 无横向溢出。
- [ ] 顶部导航锚点均可到达对应区块。
- [ ] 页面默认加载时可成功查询房型。
- [ ] 修改日期/房间数量后重新查询，价格和可售状态与 API 一致。
- [ ] 选择房型后摘要总价正确显示。
- [ ] 缺少姓名/电话时不能创建订单。
- [ ] 创建预订只产生一笔幂等订单，不绕过 PMS2 库存冻结。
- [ ] 成功页正确显示服务端返回的订单号、状态、金额与到期时间。
- [ ] 取消待支付订单后由服务端释放库存。
- [ ] 生产环境不显示本地模拟支付按钮，服务端仍拒绝模拟支付。
- [ ] 图片和酒店内容已替换/核实后才允许正式发布。

## 6. 代码阅读提示

页面脚本通过 DOM ID 与服务端 API 交互。改版时保留了既有脚本和关键 ID（如 `search-form`、`room-list`、`book-button`、`reservation-result`），后续修改 HTML 时不得随意删除或重命名，否则会破坏预订交互。页面文案不构成新的业务规则；所有库存、价格、订单与支付状态仍以服务端返回为准。


## 2026-11-12 API 安全口径校准

公开订单详情与取消接口必须使用创建预订时一次性返回的 Booking Access Token，通过 `X-Booking-Token` 请求头提交。手机号仅是联系方式，不是订单认证凭据。当前生产真实支付渠道仍未接入；mock 支付仅限允许的 dev/test 环境。
