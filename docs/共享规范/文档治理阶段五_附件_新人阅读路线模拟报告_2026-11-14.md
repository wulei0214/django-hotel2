## 二、迷路点与改进建议

**断链**：未发现硬断链——README 8 个文档链接、状态总览 §6 入口表、阅读路线/矩阵指向的文件全部实测存在。

**错误指引/矛盾入口**（按严重度）：

1. **权威 OpenAPI 快照内部的错误码形态矛盾（最重要发现）**：`openapi.json` 中 `PublicApiError` schema 描述仍为"error 为字符串（公开预订旧契约）"，但其 400/404/409/503 响应描述已写稳定码（VALIDATION_ERROR 等），README MAINT-04（2026-11-13）宣称公开端点已收敛为 `{error:{code,message},meta}`。新人拿着权威快照无法确定公开面错误体到底是字符串还是对象。
   建议：MAINT-04 重导快照时同步修正 `PublicApiError` 描述/结构；或在状态总览 §2 加一行"公开面错误体现值以 MAINT-04 后快照 actual response 为准"。
2. **接口指南的年代分层陷阱**：`PMS2接口文档与测试人员使用指南_2026-11-10.md` 自身三处数字不一致（头部 113/115、§1 102/104），且 §2.1"公开预订接口错误通常为 {error:\"...\"}"与 MAINT-04 相反。矩阵 CF-B2 行已裁定其计数为历史值，但新人通常先读指南、后读矩阵。
   建议：指南头部加粗一行"本文数字与错误格式描述为历史快照，现值仅见《PMS当前状态总览》§2"；或将 §2.1 改写为指针。
3. **验收标准的位置与路线指针错位**：阅读路线模块表写"06 验收标准"，但《PMS2.0最终开发完成与上线验收标准》在 05 目录；06 目录只有 95/96/A16 签署证据。矩阵"验收与签署"行权威也只有 06 三件，未提 05 的验收标准文件。
   建议：模块表与矩阵行改写为精确文件路径（05/…验收标准 + 06/95、96、A16 分工），或按既定迁移计划把验收标准文件挪入 06。

**三个最易迷路点**：
- 上述第 1 条（公开面错误契约形态）——后端对接公开预订 API 时必踩。
- 押金规则需读三处才能锁定现值：六项基线 §3（30% 正式规则）→ 同文件尾部"2026-11-12 校准"（服务端强制 30%、DepositPolicy 未被消费）→ 状态总览 §5（配置化待裁定）。建议在六项基线 §3.1 加一行指向状态总览 §5 的现值指针。
- 预订/入住需求分散三处（全业务中心基线 2.0 §3.5、房态库存 P0P1、六项基线的押金/Walk-in 节），模块导航表只给简称不给路径，首次拼接需多次 ls。建议模块导航表直接写文件相对路径。
