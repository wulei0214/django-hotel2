# 代码审查与质量门禁规范

> 依据：ARCHITECTURE.md §10 自动化质量与测试门禁、修改等级表；治理 V1.1 §4/§5/§8；第一阶段问题清单 P-04/P-11/P-12 与 G-01/G-05。
> 效力：专项规范，细化宪法而不冲突。

## 1. 三层门禁语义（第一阶段核实结论的固化，宪法 §10 引用本节口径）

| 层 | 时机 | 内容 | 阻断效力 |
| --- | --- | --- | --- |
| L-提交层 | 本地 git commit / pre-push | pre-commit 钩子：ruff(--fix)、ruff-format、black、mypy（对**触碰的** apps/hotel 文件；存量债务随触碰清偿——"谁改动谁清理"）；pytest 于 pre-push | 阻断；确需跳过时用 `--no-verify`，但**必须**在提交说明中注明原因与已做的人工等价校验（仅限 docs-only 或已预跑 ruff/black/mypy/pytest 的提交） |
| L-CI 层 | push/PR → main | `django-ci.yml`：lint（ruff+black，**差异范围**：仅本次变更的 apps/、hotel/ .py，`--diff-filter=ACMR`）＝硬门禁；type-check（`scripts/mypy_baseline.py check`，mypy-baseline.txt 冻结存量、**仅拦新增错误**）＝硬门禁；`manage.py check`/迁移漂移/全量测试＝硬门禁；`ci.yml`：MySQL 8.0 全量套件 + append-only 守卫安装与校验＝硬门禁 | 阻断；结果绑定具体 SHA |
| L-人审层 | 合并前 | 按本规范 §3 清单人工审查；L3/L4 变更另走《AI派活与架构变更审批规范》§3 | 一票否决 |

**工具分工（G-05 落实）**：导入排序由 Ruff I001 统一负责；独立 isort 已移除（requirements-dev、pre-commit、pyproject 同步清理）。Black 为唯一格式化权威，ruff-format 与 Black 并存期间以 Black 输出为准（两者 line-length 100，冲突时以 `black` 重排）。

## 2. 立即强制项与渐进治理项（治理 V1.1 第二阶段任务 8）

### 2.1 立即强制（新改代码，当场阻断）

1. 新增/修改的 Python 代码必须过 ruff + black + 触碰文件 mypy 零错误；
2. mypy 基线门禁：任何提交不得新增 mypy 错误（mypy-baseline.txt 冻结存量；**禁止清空/手改基线**，基线变更必须随真实清偿提交并在说明中注明清偿范围，见 `scripts/mypy_baseline.py` docstring）；
3. `manage.py check` 零问题、`makemigrations --check --dry-run` 无漂移；
4. 涉及 Model/迁移的变更必须带迁移与双库验证（SQLite+MySQL）；
5. 写路径走 Service、事务边界/锁序/幂等键遵循宪法 §7；
6. 财务/审计/PII/权限变更走 L4 审批；
7. 新增端点先更新 `apps/api/openapi_schema.py` 契约与契约测试，再实现（宪法 §8）；
8. 测试报告绑定 SHA + 真实命令 + 退出状态 + 数量。

## 3. 人工审查清单（合并方通过；一票否决项见 ✋）

**A. 架构红线**
- ✋ 新功能进 hotelapp/（宪法 §9：新需求默认不得在 hotelapp 另建重复核心业务）；
- ✋ 绕过 Service 直改核心业务 Model（宪法 §3.2）；
- ✋ 裸写 raw SQL / QuerySet.update 绕过财务/审计不可变约束（宪法 §6.1）；
- ✋ 改共享 Model 无迁移/无双库验证；
- ✋ 为同一业务建立重复 endpoint/第二套响应契约（宪法 §4）。

**B. 重复与边界**
- 新增核心对象前是否提交复用判断（宪法 §1.4）；
- 是否跨模块导入私有实现（宪法 §9）；
- 是否形成第二数据源/第二权威（宪法 §1.2）。

**C. 安全**
- 用户输入经序列化/校验层；权限走 identity 授权服务而非硬编码（宪法 §5）；
- PII 揭示走 reveal 服务 + 权限码 + reason + 审计（宪法 §5.8）；
- SQL 全参数化（Django ORM/参数绑定），无拼接。

**D. 事务与一致性**
- 多步写在同事务；失败回滚干净；幂等键+请求指纹（宪法 §7）；
- 涉及并发敏感流程：锁对象/锁序/隔离级别已定义并在 MySQL 验证。

**E. 可测性**
- 带对应测试；业务断言验证最终 DB 状态而非仅 HTTP 200（V1.1 §5）；
- 高风险流程覆盖事务回滚、重复请求、并发、不可变约束。

## 4. 提交与并行会话纪律

- 提交用显式 pathspec；`git add -A` / `git commit -a` 禁止（并行会话在途修改常态存在）；
- 暂存前 `git status --short` 核对；暂存区被他人 reset 时先核对归属再重建；
- Mimosa hook（warn 模式）提示的 staticfiles vue.js / 0012 迁移 / openapi 文档字符串类提示为**已确认误报**，不阻断也无需重复"修复"；
- pre-commit 首跑需从 GitHub 克隆钩子环境：代理在线时正常生效；代理不可用时的跳过必须按 §1 L-提交层规则注明。
