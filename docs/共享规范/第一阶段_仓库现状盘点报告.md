## 5. 十个治理域现状盘点（V1.1 任务 2/9 关联）

> 详细机制证据由治理域专项盘点产出，此处为报告级摘要；"缺口"仅陈述静态检索未命中的事实，不含推测。

### 5.1 身份认证
PMS 员工登录 `/login/`（须 DEFAULT 物业有效任职）；平台管理员登录走 `/admin/login/`（is_active+is_staff+is_superuser 三不变量，半状态 403 + `security.platform_denied` 审计）；公开注册已关闭（AUTH-01，register_view 302 至 /reserve/）。`SplitSessionMiddleware` 按 path 分流三套会话 Cookie：PMS `sessionid@/`、平台门户 `platform_sessionid@/platform/`、Admin `django_admin_sessionid@/admin/`（两份平台 Cookie 为同一 Session Key 的传输别名；历史 admin_sessionid 仅发过期指令）。`CSRF_USE_SESSIONS=True` 使 CSRF 秘密随会话域隔离。登录失败限流 `auth.login`（IP+username HMAC，5/5min，fail-closed）。强制改密 `must_change_password`（D-07）。缺口：无 handler403 自定义、无 MFA/验证码、密码强度仅 AUTH_PASSWORD_VALIDATORS 默认四件套。

### 5.2 RBAC
权限不挂 `User.groups` 用户直挂；`StaffRoleAssignment(membership, group, starts_at, ends_at)` 表示"任职期内的岗位授权"；`active_membership_key` DB 级唯一约束强制"同物业同员工仅一条 ACTIVE 任职"。校验入口 `AuthorizationService.has_permission`（**superuser 不绕过业务权限**）+ `filter_queryset_for_property`（非物业模型抛 ValueError）。权限矩阵中心 `/platform/permissions/`：version 内容 hash 乐观锁 + Group 行锁 + 高危 diff TimestampSigner 确认令牌（10 分钟）+ 保存与审计同事务；PLANNED/RETIRED 模块码整体 409。缺口：无对象级 ACL（仅到 app_label.codename + property_id 复核）；平台权限矩阵变更无 ApprovalRecord 审批流。

### 5.3 物业上下文
`PropertyContextMiddleware` 请求级绑定 `request.property/staff_membership/staff_profile`；员工取 DEFAULT 物业 ACTIVE 任职，无任职则 property=None + `security.property_context_denied` 审计（不静默回退）；**多物业切换未实现**（P1-06 单店边界，`active_property_id` 会话切换已移除，代码注释"须另立专项"）。已知口径分歧：`hotelapp/views.py::home` 在 property=None 时静默回退 DEFAULT（展示面），与 middleware 的"禁止静默回退"口径不同源（列入问题清单 P-07）。

### 5.4 PII（apps/guests）
`Guest.phone_ciphertext`/`GuestPhone.phone_ciphertext` = Fernet；`phone_hash`/`doc_no_hash` = HMAC-SHA256(DJANGO_PII_KEY, normalized)；历史明文列留列不写入（迁移 0007 已清空）。密钥 `DJANGO_PII_KEY` 独立于 SECRET_KEY（WB-123），生产缺失/长度<32 启动 fail-fast，禁止回退 SECRET_KEY。检索索引 `idx_guest_prop_hash` 等；同 guest 同号码唯一 `uq_guestphone_guest_hash`；证件占用唯一 + `register_document` 事务内 select_for_update 仲裁。揭示（`reveal_document/reveal_phone`）须独立权限码 + reason 强制 + 逐次 AuditEvent；API 层另有 DTO 级脱敏。备份恢复演练脚本 `scripts/pii_restore_drill*.py`（WB-124）。缺口：无密钥版本字段（key_version）与轮换/重加密实现（决策文档有要求，代码未落地）。

### 5.5 财务（apps/billing + apps/core）
Folio：`master_reservation_key` 唯一键保证每预订唯一 MASTER 账单（M-04）；拆账经 `FolioTransfer` 成对记录不搬迁凭证。LedgerEntry：`ImmutableLedgerEntryQuerySet` 拦 update/delete/bulk_*、`save()` 拒改已存凭证、`delete()` 抛 RuntimeError、`amount!=0` CheckConstraint、错账走红字冲销 `void_of` + 冲销审批约束 `ck_ledger_reversal_approval_link`、`reference` 唯一作入账幂等。退款三环：request（建 PENDING+ApprovalRecord）→ approve（仅审批）→ execute（强制 confirm、现金退款限本人 OPEN 班次、锁序 Shift→Payment→Refund、写 REFUND 凭证）+ reject/expire；**SoD 三人不得同一人由 3 条 DB CheckConstraint 强制**（`ck_refund_sod_request_approve/_request_execute/_approve_execute`）。夜审：两段事务（RUNNING 提交 + Property/BusinessDate 行锁串行化 → 过账事务，锁序 Stay→ReservationRoom→Reservation→Property/BusinessDate）、MAINT-02 超时恢复、重开审批 + BreakGlassRecord、`BusinessDate.open_property_key` 唯一 OPEN 营业日。对账：`scan_folio_reconciliation` 只读 7 项核对（含 WB-092 反向扫描），差异落 FolioReconciliationRun/Diff 不自动改写。MySQL append-only 守卫：`install_mysql_append_only_guards` 装 7 个触发器（audit/ledger/movement 三表 UPDATE/DELETE 一律 SIGNAL + 现金变动 INSERT 守卫），源码声明"不放 migration（账号权限不同），需在目标库手工安装"。缺口：Folio OPEN/CLOSED/VOIDED 无 DB 级流转约束（服务层仅查 `status != OPEN`）；触发器 SQLite 测试环境不覆盖。

### 5.6 审计
